## 一、发明名称

**一种低轨卫星星座多星聚合EPFD协同规避与执行时序精度保障方法**

---

## 二、技术领域

本申请提案的技术方案属于**无线通信**领域，具体涉及**卫星通信**和**物联网**子领域，以及**人工智能**辅助决策的交叉应用。

本申请提案适用于大规模LEO卫星星座多颗卫星同时飞越GEO卫星保护区域的场景，解决两个相互关联的系统级问题：①多颗LEO卫星同时工作时，单星合规而系统聚合EPFD可能超限的协调问题；②干扰规避配置指令从地面下发到卫星执行期间，因传播时延、处理时延、硬件响应时延叠加导致的执行时序精度不足问题。

## 三、现有技术的技术方案

### 3.1 公知技术背景

**LEO星座轨道特性与多星干扰叠加**：LEO星座通常由数百至数万颗卫星组成（如Starlink、OneWeb、GW等），轨道高度500~1200 km，运行速度约7~8 km/s。由于GEO卫星固定在赤道上空约35786 km处，当LEO星座在GEO卫星定点经度附近飞越时，同一时刻可能有多颗LEO卫星的下行波束方向与GEO地球站共线或接近共线，产生"多星叠加"的干扰效应。

**EPFD的系统性定义**：根据ITU-R S.1503，EPFD是一个系统级指标，表示所有NGSO（LEO）系统卫星对GEO地球站产生的等效功率通量密度之总和。ITU保护阈值EPFD_th是对全星座聚合干扰功率的约束，而非单颗卫星的约束。这意味着：即使每颗LEO卫星的单星EPFD（SS-EPFD）均低于某个分量阈值，多星叠加的聚合EPFD（AS-EPFD）仍可能超过ITU系统保护阈值。

**信号传播时延基本规律**：对于高度H = 500 km的LEO卫星，信号单程传播时延约为 H/c ≈ 1.7 ms（c为光速）；H = 1200 km时约为 4 ms。地面SCF通过馈电链路向卫星上注指令时，指令单程传播时延等于SCF馈电站至卫星距离除以光速，因卫星位置动态变化，该时延在轨道周期内持续变化（介于最小值H_min/c和斜距最大值对应的时延之间）。

**现有单星干扰规避方法**：现有方案针对每颗LEO卫星独立计算其单星干扰规避配置，SCF分别向各星上注关断指令，各S-gNB独立执行。该流程未建立跨卫星的协调机制，也未在指令时序中显式补偿传播时延。

### 3.2 最接近的现有技术方案

**现有技术A（单星独立规避方案）**：SCF分别对每颗LEO卫星评估其单星EPFD是否超过单星保护限值（由全星座保护限值按某种静态比例均分），若超限则下发关断指令至对应S-gNB。该方案的特征：
- **协调机制**：各星独立，无跨星EPFD聚合感知，无动态协调协议；
- **责任分配**：静态平均分配（每星分得等量的EPFD预算），不考虑各星的实际业务负载、轨道位置和EPFD贡献差异；
- **时序处理**：指令中仅包含规避起止时刻（基于星网时钟），未引入传播时延补偿，指令传输时延视作可忽略或由静态余量覆盖。

**现有技术B（基于预测的时间提前量设计）**：部分地面系统采用固定的时间提前量（如固定提前3秒发送指令），以粗略覆盖传播时延和处理时延。该方案的特征：
- 固定时间提前量不随卫星轨道位置动态变化，当卫星高度、仰角变化时，实际执行时序误差在不同位置有显著差异；
- 未建立执行时序偏差的闭环反馈和动态修正机制；
- 固定余量往往设置偏大（保守估计），导致规避提前开始，压缩了服务窗口。

## 四、现有技术的缺点及本申请提案要解决的技术问题

### 4.1 现有技术缺点

**缺点一：单星独立规避无法保证系统级EPFD合规**

现有技术A的单星独立规避策略忽视了多星EPFD叠加效应。当N颗LEO卫星同时可见于GEO保护区域时：
- 若使用静态平均分配（每星被允许的SS-EPFD = EPFD_th / N），则N值通常是基于最坏情况的静态估计值，导致大多数情况下各星的允许份额过于保守，造成不必要的关断；
- 若不控制N值（不感知同时在轨的干扰卫星数），则单星的允许阈值无法动态适应实际的多星叠加场景，存在系统级AS-EPFD超限风险。

**缺点二：静态责任分配未考虑业务负载差异，整体损失最大**

现有技术A对所有卫星均等分配规避责任，未考虑各星的实时业务负载（已承载用户量）。当业务量少的卫星（轻载）和业务量多的卫星（重载）同时处于干扰场景时，等量分配规避责任可能导致重载卫星在承担规避时业务中断影响较大，而轻载卫星的规避能力未被充分利用，系统整体业务损失最大化。

**缺点三：固定或无传播时延补偿导致执行时序精度低**

现有技术B的固定时间提前量设计存在以下问题：
- 传播时延随LEO卫星位置动态变化（变化幅度约2~4 ms），固定提前量在卫星仰角较低时可能不足，在仰角较高时又过于保守；
- 未分离并独立补偿各分量时延（传播时延、处理时延、PAA切换时延），整体补偿精度差；
- 无执行偏差反馈机制，错误积累后无法自我修正；
- 在精确到无线帧（10 ms）或子帧（1 ms）的调度层面，毫秒量级的执行时序误差可能导致规避"超前"（占用正常服务时隙）或"滞后"（GEO保护窗口未被及时覆盖）。

### 4.2 本申请提案要解决的技术问题

1. 如何建立多LEO卫星之间的AS-EPFD实时监测机制，在系统级感知聚合干扰态势；
2. 如何在SCF层面建立动态、负载感知的多星规避责任分配协议，最小化整体业务损失；
3. 如何设计传播时延预补偿机制，将执行时序精度从毫秒量级提升至亚毫秒量级；
4. 如何建立执行时序偏差的闭环反馈与动态修正机制，持续保持时序精度。

## 五、本申请提案的技术方案的详细阐述

### 技术方案一：多星聚合EPFD实时监测与动态协调

#### 5.1.1 系统架构：SCF多星协调器（SCF-MSC）

SCF内集成多星协调器（MSC），周期性（T_coord = 1~5 s）执行以下协调流程。MSC接入的数据源包括：①所有在轨LEO卫星的实时星历数据库；②各S-gNB通过管理响应消息上报的实时业务负载率（已使用波束数/总波束数）；③ITU-R S.1503系统EPFD保护阈值 EPFD_th_sys 和统计门限 P_threshold（超过阈值的允许百分比时间）。

#### 5.1.2 AS-EPFD实时计算

SCF-MSC对每个被保护GEO地球站 k，收集当前时刻所有处于"干扰几何关系"（轨道几何满足共线或近似共线条件）的LEO卫星集合 S_active，按以下步骤计算AS-EPFD：

**步骤1：单星EPFD贡献计算**

对集合 S_active 中的每颗卫星 j（j ∈ S_active），计算其对GEO地球站 k 的单星EPFD贡献 SS-EPFD_j（计算方法同专利1的EAE，此处引用）。

**步骤2：聚合计算**

```
AS-EPFD = Σ_{j ∈ S_active} SS-EPFD_j
```

**步骤3：超限判断**

若 AS-EPFD > EPFD_th_sys（或统计上超时比例将超过P_threshold），则触发多星协同规避流程（5.1.3节）。

#### 5.1.3 动态负载感知规避责任分配算法

当 AS-EPFD > EPFD_th_sys 时，SCF-MSC需在 S_active 集合的N颗卫星间分配规避责任，目标是**在保证 AS-EPFD 降至合规水平的前提下，最小化各星总业务中断量**。

**步骤1：计算各星调度贡献优先级（SCP_j）**

综合考虑EPFD贡献度（ρ_j）和业务负载（λ_j）：

```
ρ_j = SS-EPFD_j / AS-EPFD           （EPFD贡献比例，范围0~1）
λ_j = Used_Beams_j / Total_Beams_j  （当前业务负载率，0~1，由S-gNB上报）

SCP_j = α × ρ_j + (1-α) × (1 - λ_j)   （α为EPFD贡献权重，默认0.6）
```

**物理含义**：SCP_j越高，表示该卫星EPFD贡献大（应多承担规避责任）且业务负载低（规避时业务损失小），因此应优先被分配更多规避任务。

**步骤2：规避责任迭代分配**

从 SCP_j 最高的卫星开始，逐步升级其规避等级（IRL由低到高），每次升级后重新计算 AS-EPFD，直至 AS-EPFD ≤ EPFD_th_sys：

```
PROCEDURE Assign_Avoidance_Responsibility:
  INPUT: S_active, SS-EPFD_j, λ_j, EPFD_th_sys
  SORT S_active by SCP_j (descending)
  FOR each satellite j in sorted order:
    IF AS-EPFD ≤ EPFD_th_sys: BREAK
    Upgrade IRL_j (IRL-0→IRL-1→IRL-2→IRL-3)
    Estimate new SS-EPFD_j after IRL upgrade:
      IRL-1: SS-EPFD_j × Δ_SL （旁瓣抑制后EPFD降低因子，约0.7~0.9）
      IRL-2: SS-EPFD_j × Δ_NS （零陷后EPFD降低因子，约0.001~0.01）
      IRL-3: SS-EPFD_j = 0     （完全关断）
    Update AS-EPFD = Σ SS-EPFD_j
  END FOR
  RETURN {IRL_j} for each j ∈ S_active
```

Δ_SL 和 Δ_NS 的具体数值由SCF根据PAA天线特性预先校准，或通过仿真数据获得，作为可配置参数存储于SCF。

**步骤3：差异化IRL配置下发**

SCF-MSC将各星的 IRL_j 配置分别通过S-C1接口下发至各自S-gNB，配置信息中新增协调相关字段（见5.1.4节）。

#### 5.1.4 协调配置消息扩展字段

在干扰规避配置信息（业务波束/随遇波束）中新增以下字段，标识本次配置属于多星协调事件的一部分：

- **协调事件ID（Coord_ID，32比特）**：标识本次多星协调事件的全局唯一编号，由SCF-MSC在触发协调时生成。同一协调事件中各星收到的指令携带相同 Coord_ID；
- **协调有效期（Coord_Duration，32比特，单位：秒）**：本次协调配置的有效时长，超时后自动解除协调约束（各星恢复独立规避逻辑）；
- **本星EPFD分配份额（CES，16比特，单位：0.1 dBW/m²/MHz，偏置100dB）**：SCF分配给本星的SS-EPFD上限值，供S-gNB在本地精细化调整波束配置时参考；
- **协调星数（Coord_Count，8比特）**：本次协调事件涉及的卫星总数（即|S_active|），供运营管理系统审计。

#### 5.1.5 可选的ISL辅助协调机制

若LEO星座配备星间链路（ISL），各S-gNB可通过ISL向相邻卫星广播当前执行的规避等级和业务负载状态，形成分布式协调辅助层。SCF-MSC可利用ISL上传的实时状态数据，以更快的周期（T_ISL < T_coord）修正协调决策，在SCF与各星通信时延较大的场景下，提升协调响应实时性。ISL协调数据帧格式（新增）：
- 发送星ID（Sender_ID，32比特）
- 当前执行的IRL等级集合（IRL_Summary，每波位2比特压缩编码）
- 当前业务负载率（Load_Rate，8比特，单位0.4%）
- 本地计算的SS-EPFD（Local_EPFD，16比特）

### 技术方案二：传播时延预补偿执行时序精度保障机制

#### 5.2.1 时延链路分解

规避指令从SCF生成到S-gNB实际执行，经历如下时延链路：

```
T_total = T_prop + T_proc + T_PAA
```

- **T_prop（传播时延）**：SCF馈电站→LEO卫星，单向传播时延；
  计算方式：T_prop = R_feed(t) / c，其中 R_feed(t) 为时刻t时SCF馈电站至卫星的斜距（可从星历实时计算），c 为光速（约3×10⁸ m/s）；
  典型范围：1.7 ms（H=500km，天顶方向）~ 8 ms（H=1200km，低仰角）。

- **T_proc（S-gNB指令处理时延）**：S-gNB接收完最后一个配置包后，L3层解析指令、计算规避时隙、通知L2和PAA-CU所需的处理时延；
  典型范围：5~20 ms（取决于S-gNB计算能力和配置包数量）；
  获取方式：S-gNB在能力响应消息中上报 T_proc_cap（最大处理时延估计）。

- **T_PAA（相控阵切换时延）**：PAA-CU从接收到权值切换指令到完成权值更新并稳定发射的时延；
  典型范围：0.5~5 ms（取决于PAA硬件能力）；
  获取方式：S-gNB在能力响应消息中上报 T_PAA_cap。

#### 5.2.2 SCF实时计算T_comp并注入配置信息

SCF在生成每次规避配置信息时，计算总时延补偿值：

```
T_comp = T_prop(t_send) + T_proc_cap + T_PAA_cap + T_margin
```

其中 T_prop(t_send) 根据发送时刻的星历实时计算；T_margin 为安全余量（默认0.5 ms，可配置）。

在干扰规避配置信息中新增以下字段：

- **总时延预补偿值（T_comp，32比特，单位：微秒，范围：0~65535 μs）**：SCF计算的总时延补偿值；
- **时延参数有效标志（TD_Valid，1比特）**：1=本配置信息包含有效的T_comp，S-gNB应使用T_comp进行预补偿；0=忽略T_comp（用于向旧版S-gNB的兼容发送）；
- **T_prop分量（T_prop_field，16比特，单位：微秒）**：仅供S-gNB日志记录和诊断使用；
- **配置生成时刻时间戳（Gen_Timestamp，64比特，单位：纳秒，使用GNSS时间）**：SCF生成本配置包时的GNSS时间戳，供S-gNB验证时延参数的时效性（若接收时刻与Gen_Timestamp差异>T_comp×2，说明传输时延异常）。

#### 5.2.3 S-gNB时序预补偿单元（TPC）执行流程

S-gNB中的时序预补偿单元（TPC）集成于L3层，按以下流程处理规避时序：

**步骤1：时延参数有效性验证**

TPC读取TD_Valid字段；若有效，继续步骤2；否则按原始时间参数执行（向下兼容）。

**步骤2：时间戳时效性检查**

TPC将Gen_Timestamp与本地GNSS时间 T_local 对比：
- 若 T_local - Gen_Timestamp_GNSS > T_comp × 2，则认为配置包传输时延异常（可能由链路中断后重传导致），丢弃T_comp补偿，向SCF上报时效性警告；
- 否则进行正常时序预补偿。

**步骤3：规避时刻预补偿计算**

对配置信息中的每个规避时间段 [start, end]：
```
start' = start - T_comp
end'   = end   - T_comp
```

TPC将调整后的时间段 [start', end'] 通知L2调度层和PAA-CU，作为实际的规避触发时刻。

**步骤4：PAA-CU权值预加载（优化）**

对于提前量充足（start' - T_local > T_PAA_cap + T_margin）的情况，PAA-CU在 start' - T_PAA_cap 时刻开始计算并预加载零陷或旁瓣抑制权值（不发射，权值已就绪），在 start' 时刻即时切换激活，进一步减少权值切换引起的过渡时间不确定性。

#### 5.2.4 执行时序偏差闭环反馈机制

S-gNB-TPC执行规避后，可测量并上报实际执行时序偏差，形成闭环校正：

**S-gNB侧测量**：
- 记录L2实际停止调度的起始帧号和子帧号，换算为GNSS绝对时间 T_exec_actual；
- 计算执行偏差：ΔT = T_exec_actual - start（正值表示滞后，负值表示超前）；

**上报与SCF校正**：
- TPC在下一次管理响应消息中附加"执行时序偏差上报"字段：
  - 被报告配置的版本号（Reported_Config_Ver，32比特）；
  - 执行时序偏差（Delta_T，16比特，单位：100微秒，有符号数，范围：-3276.8~+3276.7 ms）；
- SCF收到ΔT后，动态修正后续配置的T_margin：
  ```
  T_margin_new = T_margin_old + β × ΔT   （β为学习率，默认0.3）
  T_margin_new = clip(T_margin_new, 0, T_margin_max)   （限制在合理范围内）
  ```
- 经过若干次迭代，T_margin 收敛至最优值，系统时序误差控制在±0.5 ms以内。

#### 5.2.5 异常场景处理

**场景一：T_comp > (start - T_current_uplink_time)（来不及预补偿）**
- 当规避开始时间与当前SCF发送时刻之差小于T_comp时，说明配置下发已过晚，无法实现完整的提前补偿。
- S-gNB-TPC检测到此情况后，立即以最快速度执行规避（忽略提前量），并向SCF上报"晚到警告"（Late_Arrival_Warning）。
- SCF收到警告后，将下一轮配置的生成时间提前 T_comp + T_prop_extra，避免再次发生。

**场景二：S-gNB GNSS时钟与SCF时钟漂移超限**
- TPC定期（每60秒）通过管理消息进行时钟同步校验；若时钟漂移超过1 ms，向SCF申请重新同步；SCF通过同步消息携带最新GNSS时间戳，辅助S-gNB校正本地时钟。

## 六、本申请提案的关键点和欲保护点

按照重要性从高到低排列：

1. **多星聚合EPFD（AS-EPFD）实时监测与超限判断机制**：SCF-MSC周期性收集所有处于干扰几何关系的LEO卫星的SS-EPFD，计算AS-EPFD并与ITU系统级保护阈值比较，触发协同规避流程；

2. **基于SCP_j（调度贡献优先级）的动态规避责任分配算法**：综合EPFD贡献比例ρ_j和业务负载率λ_j，计算各星SCP_j，按SCP_j由高到低迭代分配IRL升级任务直至AS-EPFD合规；

3. **协调配置消息扩展字段设计**：含Coord_ID（协调事件唯一标识）、Coord_Duration（有效期）、CES（本星EPFD份额）、Coord_Count（协调星数）的消息格式；

4. **实时T_comp计算方法**：SCF根据当前星历计算T_prop(t_send)，结合T_proc_cap和T_PAA_cap，生成精确的T_comp，并携带Gen_Timestamp注入配置信息；

5. **S-gNB-TPC时序预补偿执行流程**：包括时效性验证、[start', end']计算、PAA-CU权值预加载优化；

6. **执行时序偏差ΔT闭环反馈与T_margin自适应修正机制**：S-gNB测量实际执行时刻偏差并上报，SCF以学习率β动态收敛T_margin，实现时序精度自优化；

7. **可选的ISL辅助分布式协调机制**：S-gNB通过ISL广播规避状态和负载数据，辅助SCF-MSC实现更高频的协调决策。

## 七、与现有技术相比，本申请提案有何技术优点

**优点一：系统级ITU合规性从"尽力而为"提升至"主动保障"**
现有技术的单星独立规避无法保证AS-EPFD合规性。本方案的SCF-MSC实时监测AS-EPFD并主动分配规避责任，将系统合规保障从被动的概率性合规（依赖静态保守估计）提升为主动的确定性合规，避免了潜在的ITU违规风险和对GEO运营商的干扰赔偿风险。

**优点二：整体业务损失最小化，比静态均等分配减少业务中断**
静态均等分配使所有卫星承担相同的规避量，忽视了业务负载差异。本方案通过SCP_j优先让轻载、高贡献度的卫星承担更多规避，在相同AS-EPFD降低目标下，比静态均等分配减少约20%~40%的有效用户服务中断（依实际负载分布而定）。

**优点三：执行时序精度从"毫秒级"提升至"亚毫秒级"**
现有技术忽略或粗略处理传播时延，在LEO典型轨道场景下执行误差约5~15 ms。本方案的T_comp机制可将执行误差降至±0.5 ms以内，满足5G NR 1 ms子帧调度精度要求，实现规避时段与设计时段的精确对齐，避免"规避滞后"导致的GEO保护窗口漏洞。

**优点四：闭环自学习提升长期时序稳定性**
通过ΔT反馈和T_margin自适应调整，系统可在运行中持续优化时序精度，适应S-gNB处理时延的长期漂移和PAA切换时延的硬件老化变化，无需人工重新标定。

## 八、发散思维以及规避方案思考

**规避方向一（分布式协调替代集中式MSC）**：使用者可能利用ISL在各卫星间执行完全分布式的EPFD协商，无需SCF-MSC介入。
*建议*：权利要求中描述"多个LEO卫星通过集中式或分布式方式协调各星的规避责任，共同满足AS-EPFD约束"，覆盖分布式路径。

**规避方向二（使用者自主测量传播时延）**：使用者在S-gNB上集成传播时延自主测量能力（如利用GNSS时间戳往返测量），不依赖SCF下发T_comp，自主计算补偿量。
*建议*：权利要求表述"S-gNB根据自主测量或接收到的时延参数，对规避执行时刻进行超前调整"，覆盖自主测量路径。

**规避方向三（不同SCP分配函数）**：使用者改变ρ_j和λ_j的组合权重（如使用非线性函数或机器学习模型计算优先级）。
*建议*：主权利要求保护"基于各星EPFD贡献度与业务负载两个维度进行优先级排序后分配规避责任"的通用框架，具体函数形式在从属权利中保护。

**规避方向四（使用更粗粒度的时延补偿）**：使用者仅补偿传播时延而忽略T_proc和T_PAA。
*建议*：主权利要求中将时延补偿描述为"补偿传播时延、处理时延和/或天线切换时延中的至少一项"，覆盖不同组合。

## 九、本申请提案的商业价值

多星聚合EPFD协调解决了LEO星座ITU合规的核心难题，是大规模LEO星座商业化运营的必备能力。随着全球LEO星座规模扩大（Starlink已超6000颗，计划超4万颗），多星叠加干扰问题日益突出，本方案的商业价值随星座规模增长而提升。时序精度保障机制直接影响GEO保护的可靠性，对希望在与GEO共存场景下获得更多商用频谱资源的LEO运营商具有战略价值。本方案可作为与ITU和各国监管机构谈判频率协调的技术背书，具有明显的政策合规价值。
