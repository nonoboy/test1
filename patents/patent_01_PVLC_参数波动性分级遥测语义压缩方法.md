## 一、发明/实用新型名称

**名称：一种基于参数波动性分级的卫星遥测数据语义压缩方法**

---

## 二、所属技术领域

本发明涉及卫星通信与星务管理技术领域，特别是涉及一种面向卫星遥测数据传输的语义感知压缩方法，可应用于低轨、中轨、高轨各类卫星的星地遥测下行链路，尤其适用于慢遥测（Housekeeping Telemetry，HK-TM）数据的高效压缩传输场景。

---

## 三、现有技术（背景技术）

**背景技术：**

卫星星务管理系统通过遥测（Telemetry，TM）链路实时下传卫星平台和有效载荷的工作状态参数，包括温度、电压、电流、姿态角、设备状态码等。这些参数统称为慢遥测数据（Slow Telemetry），是地面对卫星实施健康管理和故障诊断的重要依据。

**现有技术的主要局限性体现在以下方面：**

**1. CCSDS标准体系未提供语义级压缩机制**

国际空间数据系统咨询委员会（CCSDS，Consultative Committee for Space Data Systems）是航天界公认的遥测遥控标准组织，其制定的空间包协议（CCSDS 133.0-B）和TM空间数据链路协议（CCSDS 132.0-B）规定了遥测数据的封装格式与传输规程。CCSDS 121.0-B虽定义了基于Rice/DPCM算法的通用无损数据压缩，但该方案是对数据块进行盲压缩，不利用遥测参数的语义信息（如参数的物理含义、变化规律等），压缩效率有限，且压缩/解压缩处理时延较大，难以满足实时遥测流的低时延需求。

**2. 传统遥测帧结构存在大量冗余**

卫星慢遥测帧通常采用固定格式，每帧携带全部参数的完整取值，不论该参数是否发生变化。实际工程经验表明，在卫星正常工作期间，90%以上的慢遥测参数在相邻帧间保持不变或变化幅度极小（如温度变化通常不超过0.1°C/秒）。因此，每帧重复传输大量未变化数据是对宝贵遥测信道带宽的严重浪费。

**3. 现有技术未利用参数异构波动特性**

不同遥测参数的波动特性差异显著：软件版本号、设备编号等配置参数在整个在轨寿命内几乎不变；热控温度、母线电压等参数缓慢连续变化；故障标志位、工作模式等参数偶发性突变。现有遥测传输协议对所有参数采用统一的传输策略，未能根据参数波动特性进行差异化压缩处理，导致整体压缩效率低下。

**4. 地面移动通信领域的对比参考**

第三代合作伙伴计划（3GPP）在其用户面协议栈中定义了鲁棒头部压缩协议（ROHC，Robust Header Compression，RFC 5795），通过维护上下文信息并仅传输变化字段，将IP/UDP/RTP协议头从40字节压缩至2-4字节，压缩率超过90%。然而，ROHC面向的是通信协议头部（固定格式字段），而非卫星遥测数据负载（语义丰富的参数值域），两者的数据特征和应用场景存在本质差异，不能直接移植。

综上所述，现有技术缺乏一种能够充分利用遥测参数异构波动特性、实现遥测数据语义级增量压缩的高效方法，导致卫星遥测信道带宽利用率低，制约了慢遥测参数的监测密度和更新频率。

## 四、发明/实用新型内容

### 1. 要解决的技术问题

本发明要解决的核心技术问题是：现有卫星遥测传输协议未利用遥测参数的语义信息和异构波动特性，导致遥测帧中存在大量冗余数据，信道带宽利用率低，限制了可传输的遥测参数数量和更新频率。

具体地，本发明要解决以下子问题：

（1）如何根据参数波动特性对遥测参数进行合理分类，并设计差异化的压缩策略；

（2）如何在星上计算资源受限的条件下高效实现上述分级压缩，并保证压缩后数据的可靠还原；

（3）如何在保证关键参数完整性的前提下，实现压缩模式的动态调整；

（4）如何设计兼容CCSDS标准体系的压缩遥测帧格式。

### 2. 为解决技术问题而采用的技术方案

**技术方案描述：**

本发明提出一种基于参数波动性分级的卫星遥测数据语义压缩方法（PVLC，Parameter Volatility Level Compression），其核心思想是：根据遥测参数的历史波动统计特征，将所有遥测参数划分为三个波动性等级，并针对每个等级采用差异化的压缩策略，最终将压缩后的增量数据封装为压缩遥测帧进行传输。

**技术方案由以下核心模块组成：**

**（一）参数波动性分级模块**

将全部遥测参数按波动性分为三个等级（A、B、C级），分级判据如下：

- **A级（静态参数）**：在连续K₁帧（默认K₁=1000帧，可通过遥控上行修改）内取值从未改变，或参数逻辑属性标注为配置型参数（如软件版本号、设备序列号、在轨注入常数等）。A级参数不在常规遥测帧中传输其数值，仅定期（每N₁帧）传输全部A级参数的集合哈希校验值，用于星地上下文一致性验证。

- **B级（缓变参数）**：在连续K₂帧内，相邻帧间取值变化的绝对值不超过预设阈值ΔB（由参数量程和精度确定），且变化具有连续性（无突变）。B级参数采用自适应差分编码（ADC，Adaptive Differential Coding）：传输当前值与上一帧值的差值（残差），残差采用自适应量化位宽（4位、8位或16位）编码。

- **C级（事件参数）**：取值可能发生突变，包括故障标志位、工作模式字、事件计数器等。C级参数采用条件传输策略：仅在当前帧取值与上一帧不同时，将参数ID与完整参数值一并传输。

分级表（Parameter Level Table，PLT）存储于星上遥测处理单元的非易失性存储器中，初始版本在卫星出厂时配置，支持通过遥控上行命令在轨更新。

**（二）星上压缩编码模块**

压缩编码按以下步骤执行：

步骤1：读取当前遥测采样周期的所有参数原始值，与上一帧缓存值进行比较；

步骤2：对B级参数，计算差值residual[i] = value[i] - prev_value[i]，判断残差范围，选择最短能够无损表达该残差的量化位宽（4/8/16 bit），记录位宽选择标志；

步骤3：对C级参数，检查是否发生变化，若变化则将参数ID（16位）和完整参数值加入C级变化列表；

步骤4：计算A级参数集合哈希（采用CRC-16或FNV-1a算法，星上开销低），判断是否需要附加哈希字段（仅每N₁帧携带一次，或A级参数实际发生变化时立即携带）；

步骤5：按下述压缩帧格式将上述信息封装为压缩遥测帧（C-TM Frame），嵌入CCSDS空间包用户数据域。

**（三）压缩遥测帧格式设计**

压缩遥测帧（C-TM Frame）格式定义如下（字节偏移从0开始）：

```
字节偏移  字段名称             位宽    说明
─────────────────────────────────────────────────────────────────────
0         PVLC版本号           4 bit   协议版本标识，当前版本=0x1
0         压缩标志位组         4 bit   bit3: A级哈希存在标志
                                       bit2: B级差分数据存在标志
                                       bit1: C级变化列表存在标志
                                       bit0: 压缩失效回退标志
1-2       帧序列号             16 bit  压缩帧计数器（循环）
3-4       时间戳增量           16 bit  相对上一压缩帧的时间偏移(ms)
─────────────── 以下字段根据压缩标志位条件性存在 ───────────────────
[可选] 2字节  A级哈希校验码   16 bit  全部A级参数的CRC-16校验值
[可选] ≤N/8字节 B级变化位图  ceil(NB/8) byte  NB为B级参数总数，
                                               每bit对应一个B级参数，
                                               1=本帧有变化，0=与上帧相同
[可选] 可变   B级残差列表    可变    仅包含位图中置1参数的残差值，
                                    每个残差值前缀2bit量化位宽标志：
                                    00=4bit, 01=8bit, 10=16bit, 11=32bit
[可选] 可变   C级变化列表    可变    格式：[2字节参数ID + N字节完整值] × M
                                    M为本帧有变化的C级参数数量
[必须] 2字节  CRC校验         16 bit  覆盖全部PVLC帧内容的CRC-16校验
─────────────────────────────────────────────────────────────────────
```

**（四）地面解压缩还原模块**

地面接收端维护与星上相同的参数级别表（PLT）和参数上下文缓存（PCC，Parameter Context Cache）。解压缩按以下步骤执行：

步骤1：解析压缩标志位，确定各字段存在性；

步骤2：若A级哈希字段存在，验证与本地PCC的一致性；不一致时触发上下文重同步请求；

步骤3：对B级参数，根据位图确定哪些参数发生变化，用残差值更新对应参数的PCC取值：new_value[i] = prev_value[i] + residual[i]；

步骤4：对C级参数，直接用接收到的完整值更新PCC；

步骤5：从PCC输出所有参数的完整值（无论当前帧是否携带），供下游遥测处理使用。

**（五）在轨自适应分级动态调整**

星上遥测处理单元持续统计各参数的历史波动情况，按以下规则自动调整参数等级（触发时机：每M帧一次统计周期）：

- 若C级参数在最近K₂帧内取值不变，自动升级为B级；
- 若B级参数在最近K₁帧内取值不变，自动升级为A级；
- 若A级参数发生任意变化，立即降级为C级并触发完整值传输；
- 若B级参数残差超过量程的30%（预示大幅跳变），临时降级为C级处理。

参数等级调整记录在压缩帧中通过专用字段通知地面，以保持星地PLT同步。

### 3. 技术方案基础上的改进与变形

**（1）A级参数哈希的多级保护机制**

在基础方案中A级哈希为单一CRC-16。改进方案中，可将A级参数按子系统分组（如热控组、电源组、姿轨控组等），每组独立计算哈希，若某组哈希不一致，仅触发该子系统参数的重同步，而不影响其他组的压缩状态，从而减少重同步开销。

**（2）B级残差的预测增强**

在基础差分编码基础上，可引入一阶线性预测：predicted[i] = prev_value[i] + (prev_value[i] - prev2_value[i])，即基于前两帧的线性外推，传输预测残差（实际值 - 预测值）而非简单差分。对于温度、电压等缓变量，预测残差通常接近零，可进一步减少编码位宽。

**（3）参数等级表的地面配置与上行注入**

PLT初始版本由地面在卫星发射前配置，但在轨运行过程中，地面运控人员可根据卫星状态变化（如进入特殊轨道段、载荷开关机等），通过遥控上行命令动态更新PLT，临时提升特定参数的传输优先级（强制降级为C级完整传输）。

**（4）压缩失效保护机制**

当检测到帧序列号不连续（帧丢失）时，发送端在下一帧的压缩标志位中置位"压缩失效回退标志"，并连续发送N_recovery帧全量遥测帧（所有参数携带完整值），以重建地面接收端的参数上下文，随后恢复压缩模式。

**（5）多压缩流并行处理**

对于拥有多个遥测数据采集单元（如主份TMTC、备份TMTC、载荷管理单元等）的卫星，可为每个单元维护独立的压缩上下文，并行进行压缩处理，各压缩流通过不同的CCSDS APID（Application Process Identifier，应用进程标识符）区分。

### 4. 有益效果

**有益效果：**

（1）**显著提升信道带宽利用率**：在卫星正常工作状态下（约90%参数不变或缓变），PVLC方法的压缩率可达85%-95%，与传统全量传输相比，同等信道带宽条件下可传输约10-20倍数量的遥测参数，极大扩充了慢遥监测的覆盖面。

（2）**低星上计算开销**：差分计算、位图生成等操作均为简单整数运算，对星上嵌入式处理器（如SPARC V8、ARM Cortex-R系列）的算力要求极低，典型处理时延不超过1ms，不影响遥测实时性。

（3）**语义感知的差异化保护**：通过三级分类，确保关键事件参数（C级）以完整值实时传输，保证故障监测的可靠性；同时对稳定参数（A级）施以最高压缩率，实现安全性与效率的最优平衡。

（4）**兼容CCSDS标准**：PVLC压缩帧嵌入CCSDS空间包的用户数据域，不改变空间包协议头部格式，对现有星地链路的物理层、数据链路层透明，无需改动星地接口约定，工程实施风险低。

（5）**支持在轨自适应优化**：参数等级动态调整机制可根据卫星实时状态自适应优化压缩策略，无需地面干预，提升了系统的自主化水平。

（6）**可靠的上下文同步机制**：A级哈希校验和压缩失效回退机制共同保障了长期运行中星地压缩上下文的一致性，防止因帧丢失导致的解压缩错误持续蔓延。

## 六、具体实施方式

**具体实施方案如下：**

以某低轨卫星（LEO）星务管理系统为例，该卫星配置遥测参数共256个，按照以下步骤实施PVLC方法：

**实施步骤一：参数分级表（PLT）初始化**

在卫星出厂测试阶段，根据各参数的工程定义文件（ICD），对256个参数进行初始分级：

- A级（静态参数）：软件版本号（4个）、设备序列号（8个）、轨道参数注入值（6个）、热控设定点（12个）= 共30个参数，占比11.7%。
- B级（缓变参数）：热控测温点（48个）、电源母线电压/电流（32个）、姿态角度/角速度（24个）、载荷温度（16个）= 共120个参数，占比46.9%。
- C级（事件参数）：各设备工作状态码（36个）、故障标志字（32个）、模式字（8个）、事件计数器（30个）= 共106个参数，占比41.4%。

PLT以查找表形式存储于星上遥测处理单元的EEPROM中，表项格式为：[参数ID(16bit)][参数等级(2bit)][量化精度(4bit)][历史统计计数(10bit)]，共256×4=1024字节，存储开销极小。

**实施步骤二：压缩编码实现**

星上遥测处理单元（采用SPARC V8 LEON3处理器）每秒执行一次压缩编码周期：

```
伪代码（星上压缩主流程）：
─────────────────────────────────────────────────────────────
procedure PVLC_Encode(current_values[256], context_cache[256]):
    // 初始化压缩帧缓冲区
    frame_buf = new ByteBuffer(512)
    flags = 0x00
    b_bitmap = new Bitmap(120)  // B级参数数=120
    b_residuals = new ByteBuffer(256)
    c_changes = new ByteBuffer(256)
    
    // A级处理
    a_hash = CRC16(current_values[A_PARAM_IDs])
    if a_hash != context_cache.a_hash OR frame_count % N1 == 0:
        flags |= 0x08  // A级哈希存在标志
        context_cache.a_hash = a_hash
    
    // B级处理
    for each B-class param i:
        residual = current_values[i] - context_cache[i]
        if residual != 0:
            b_bitmap.set(i)
            bits_needed = select_quantization(residual)  // 4/8/16/32 bit
            b_residuals.write(bits_needed_flag, residual)
            context_cache[i] = current_values[i]
    if b_bitmap.any_set():
        flags |= 0x04  // B级数据存在标志
    
    // C级处理
    for each C-class param j:
        if current_values[j] != context_cache[j]:
            c_changes.write(param_id[j], current_values[j])
            context_cache[j] = current_values[j]
    if c_changes.size() > 0:
        flags |= 0x02  // C级变化存在标志
    
    // 组帧
    frame_buf.write(PVLC_VERSION | flags)  // 字节0
    frame_buf.write(frame_counter++)       // 字节1-2（16bit）
    frame_buf.write(time_delta)            // 字节3-4（16bit）
    if flags & 0x08: frame_buf.write(a_hash)
    if flags & 0x04: frame_buf.write(b_bitmap, b_residuals)
    if flags & 0x02: frame_buf.write(c_changes)
    frame_buf.write(CRC16(frame_buf))
    
    return frame_buf
─────────────────────────────────────────────────────────────
```

**实施步骤三：压缩帧封装与发送**

PVLC压缩帧作为数据负载，封装入CCSDS空间包（Space Packet）的用户数据域，APID设为专用值（如0x200，用于区分压缩遥测流与原始遥测流），经CCSDS TM数据链路协议封装后，通过S波段或X波段下行链路传输至地面站。

**实施步骤四：地面解压缩还原**

地面遥测接收软件解析CCSDS空间包后，识别APID=0x200的包为PVLC压缩帧，调用PVLC解码器：

（a）检查帧序列号连续性，若不连续则标记上下文不确定，发出重同步告警；
（b）若存在A级哈希，与本地缓存比较，不一致时记录A级参数可能已变化，向运控系统发出告警；
（c）根据B级位图，将残差值还原为完整参数值：new_val = cache_val + residual；
（d）直接写入C级变化的完整值；
（e）输出所有256个参数的完整值（未更新的参数直接从缓存读取），完成解压缩。

**实施步骤五：在轨动态自适应调整示例**

卫星进入地影后，热控温度参数开始快速变化（变化率可达1°C/分钟），B级温度参数的残差超过原量化阈值：星上动态调整引擎将这些参数的量化精度自动从4bit提升至8bit，并通过压缩帧的级别调整字段通知地面，地面同步更新PLT，保证压缩精度满足热控监测需求。

## 七、技术创新点概括

本方案重点要保护如下几方面的创新点：

1）**参数波动性三级分类方法**：首次提出将卫星遥测参数按静态（A级）、缓变（B级）、事件（C级）三类进行语义分级，并针对每类设计差异化压缩策略的方法。

2）**A级参数哈希替代传输机制**：A级静态参数以周期哈希校验值代替参数值传输，实现极高压缩率的同时通过哈希比对保障数据一致性的技术手段。

3）**B级自适应量化差分编码**：B级缓变参数采用自适应量化位宽（4/8/16/32 bit）的差分残差编码方法，根据残差大小动态选择最短编码位宽，兼顾压缩率与精度。

4）**参数级别在轨动态自适应调整机制**：基于历史帧统计自动触发参数波动等级升降级的方法，无需地面干预实现压缩策略的自适应优化。

5）**压缩遥测帧格式设计**：一种兼容CCSDS空间包协议的压缩遥测帧结构，通过标志位条件性携带各级压缩数据，最小化帧开销。

6）**压缩失效安全回退机制**：在检测到帧丢失时自动切换为全量传输模式、重建上下文、恢复压缩模式的完整失效恢复流程。
