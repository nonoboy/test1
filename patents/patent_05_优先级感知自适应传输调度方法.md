## 一、发明/实用新型名称

**名称：一种基于参数优先级与信道质量感知的卫星遥测自适应压缩传输调度方法**

---

## 二、所属技术领域

本发明涉及卫星星务管理系统技术领域，特别是涉及一种将遥测参数安全等级分类、测控信道实时质量感知与压缩传输调度决策相结合的自适应遥测传输方法。该方法通过对不同安全等级遥测参数实施差异化的压缩传输策略，并根据信道质量动态调整传输调度方案，在保障关键参数安全传输的前提下，最大化利用有限的遥测信道带宽。

---

## 三、现有技术（背景技术）

**背景技术：**

**1. 卫星遥测信道的带宽有限性**

卫星遥测下行链路的可用带宽受限于卫星发射功率、天线增益、星地距离以及信道条件。典型低轨卫星S波段遥测链路可用带宽为4-32kbps，而随着卫星平台功能复杂化和有效载荷增多，需要传输的遥测参数数量大幅增加，带宽需求持续增长，带宽供需矛盾日益突出。

**2. 现有遥测传输系统的两大缺陷**

**缺陷一：单一传输策略，无差异化优先级**

现有卫星遥测系统通常按照固定帧格式和固定帧率，将所有遥测参数以相同帧率统一下传，不区分参数的安全重要性。这种"一刀切"策略存在以下问题：

- 关键安全参数（如热控超温告警、电源过流告警、姿控模式字）与次要监测参数（如非关键设备温度、历史数据统计值）占用相同带宽，导致带宽分配效率低；
- 当信道条件恶化（如深度衰落、雨衰、遮挡）导致可用带宽降低时，所有参数的更新频率同步降低，关键参数的监测频率也随之下降，增加了安全风险；
- 无法针对特殊任务阶段（如载荷开机、轨道机动）动态提升特定参数的传输优先级。

**缺陷二：未利用弧段带宽富余进行补传**

低轨卫星每次过顶弧段（约8-15分钟/次，每天4-6次），弧段内测控站接收信号强度会随卫星仰角而变化。仰角高（>30°）时信道质量好、带宽富余，仰角低（<10°）时信道质量差、带宽受限。现有遥测系统不感知这种动态变化，在富余时段未能高效利用额外带宽传输更多遥测数据，在受限时段也未能主动降低次要参数传输，导致关键参数在信道恶化时得不到优先保障。

**3. 通信领域QoS机制的参考与局限**

互联网QoS（Quality of Service）和移动通信网络QoS机制（如3GPP的DRB优先级调度、5G NR的SPS/Semi-persistent Scheduling）为不同业务类型设置差异化调度优先级，具有重要参考价值。然而：

- 这些机制面向实时连续业务（如语音、视频流），假设流量可动态调节；而卫星遥测有固定采样周期，"丢帧"意味着数据永久丢失而非延迟；
- 互联网QoS基于双向实时反馈，而卫星遥测为单向异步传输；
- 现有文献和专利中无针对卫星遥测参数优先级感知的系统性调度方案。

## 四、发明/实用新型内容

### 1. 要解决的技术问题

本发明要解决的核心技术问题是：在遥测信道带宽有限且动态变化的条件下，如何根据遥测参数的安全重要性等级和当前信道质量，自适应地为不同等级参数分配传输资源（带宽和帧率），保障关键参数的实时监测，同时最大化利用富余带宽提升次要参数的监测密度。

具体子问题：

（1）如何定义遥测参数安全等级体系，并设计与之对应的差异化传输策略；

（2）如何实现星上信道质量的实时感知（包括误码率、接收信号强度等），并映射为传输能力等级；

（3）如何设计多级自适应传输调度算法，动态决策各等级参数的帧率、压缩等级和传输顺序；

（4）如何实现降级参数数据的星上暂存与弧段富余带宽补传，确保数据不丢失。

### 2. 为解决技术问题而采用的技术方案

**技术方案描述：**

本发明提出一种基于优先级与信道质量感知的遥测自适应传输调度方法（PACT，Priority-Aware and Channel-adaptive Telemetry），包含参数优先级分级体系、信道质量感知模块、自适应调度引擎和低优先级数据暂存/补传机制四个核心部分。

**（一）参数优先级分级体系**

将全部遥测参数按安全重要性分为四个优先级：

**P0级（实时关键级）**：
- 含义：对卫星安全至关重要，任何时刻必须实时可用的参数；
- 典型参数：热控系统超温告警位、电源系统过流/欠压告警位、姿控系统工作模式字、关键设备开关机状态字、星上自主安全控制系统状态字；
- 传输要求：永远以全量、无压缩方式传输，不受信道质量影响，帧率≥1次/采样周期；
- 数量约束：P0级参数数量应严格控制（建议<32个），确保在最恶劣信道条件下也能完整传输。

**P1级（重要监测级）**：
- 含义：对卫星状态评估非常重要，需要较高频率监测的参数；
- 典型参数：主要热控测温点（关键部位）、主电源参数（母线电压/电流）、主要姿态参数（三轴姿态角）、主发动机工作参数；
- 传输要求：信道正常时全量传输，信道降级时允许轻度压缩（如PVLC B级差分）；
- 允许最低帧率：不低于原始帧率的50%。

**P2级（常规监测级）**：
- 含义：常规健康状态监测所需参数；
- 典型参数：次要测温点、辅助电源参数、冗余设备状态、姿控辅助参数；
- 传输要求：信道正常时中度压缩传输，信道降级时允许帧率降至原始帧率的25%；
- 允许最高压缩等级：PVLC全压缩（含A级哈希替代）。

**P3级（慢遥/归档级）**：
- 含义：非实时需要、主要用于事后分析的低优先级参数；
- 典型参数：非关键设备温度、老化监测参数、科学载荷辅助参数、历史统计值；
- 传输要求：信道正常时深度压缩传输，信道降级时可暂停实时传输（数据星上缓存）；
- 弧段富余带宽时批量补传。

**（二）信道质量感知模块**

星上信道质量感知通过以下方式实现：

**方法1：基于TC帧接收质量推断（适用于双向测控模式）**

在TC/TM双向测控模式下，星上接收TC帧时，提取TC帧的CLTU（Channel Access Data Unit）同步字锁定状态和TC帧CRC错误率，作为上行信道质量指示。考虑到上下行信道通常相关性较高（同一星地链路），上行信道质量可作为下行信道质量的代理估计。

**方法2：下行链路质量自估计**

若卫星配备信道质量自评估模块（如基于发射功率余量、星历预测的信噪比估算），可直接估计下行信道当前SNR（信噪比）：

```
SNR_estimate(t) = EIRP_tx - FSPL(t) - receiver_noise_floor
FSPL(t) = 20×log10(d(t)) + 20×log10(f) + 20×log10(4π/c)
d(t)：当前星地距离（由轨道预报计算）
f：下行频率
```

**信道质量等级划分**：

| 质量等级 | 信道条件 | 判断依据 |
|---|---|---|
| Q3（优良） | SNR > 门限+6dB，BER<10^-7 | 正常高仰角弧段 |
| Q2（正常） | SNR = 门限±3dB，BER≈10^-6 | 正常低仰角弧段 |
| Q1（降级） | SNR < 门限-3dB，BER≈10^-5 | 低仰角/部分遮挡 |
| Q0（应急） | SNR < 门限-9dB，BER>10^-4 | 严重遮挡/深衰落 |

**（三）自适应传输调度引擎**

调度引擎根据当前信道质量等级（Q0-Q3）和参数优先级（P0-P3），按照以下调度矩阵决定每个优先级的传输策略：

```
调度矩阵（行：参数优先级，列：信道质量等级）

              Q3(优良)      Q2(正常)      Q1(降级)      Q0(应急)
P0(关键)   │全量×1Hz    │全量×1Hz    │全量×1Hz    │全量×1Hz    │
           │            │            │            │（占用全部  │
           │            │            │            │可用带宽）  │
P1(重要)   │全量×1Hz    │轻压×1Hz    │轻压×0.5Hz  │暂停(缓存)  │
P2(常规)   │中压×1Hz    │中压×0.5Hz  │深压×0.25Hz │暂停(缓存)  │
P3(慢遥)   │深压×0.5Hz  │深压×0.25Hz │暂停(缓存)  │暂停(缓存)  │
           └────────────┴────────────┴────────────┴────────────┘

注：×N Hz表示实际传输帧率；"全量"=无压缩；
"轻压"=CCSDS-HCP+基础差分；"中压"=PVLC；"深压"=PVLC+PDC-OM
```

调度引擎每帧（1秒）执行一次调度决策：

```伪代码
procedure PACT_Schedule(Q_level, available_BW):
    // 预留P0带宽
    BW_P0 = get_P0_bandwidth()  // 固定值，≤25% available_BW
    BW_remaining = available_BW - BW_P0
    
    // 分配P1带宽
    if Q_level >= Q1:
        BW_P1 = min(get_P1_bandwidth(Q_level), 0.5 × BW_remaining)
        BW_remaining -= BW_P1
    else:
        // Q0时P1数据缓存
        enqueue_to_buffer(P1_data)
    
    // 分配P2带宽
    if Q_level >= Q2:
        BW_P2 = min(get_P2_bandwidth(Q_level), 0.5 × BW_remaining)
        BW_remaining -= BW_P2
    else:
        enqueue_to_buffer(P2_data)
    
    // 剩余带宽分配P3（或补传缓存数据）
    if Q_level == Q3 AND buffer_not_empty():
        // 优先补传缓存数据
        dequeue_from_buffer(BW_remaining)
    elif Q_level >= Q2:
        transmit_P3_compressed(BW_remaining)
    else:
        enqueue_to_buffer(P3_data)
```

**（四）低优先级数据星上暂存与弧段补传机制**

当信道质量降至Q1/Q0时，P1/P2/P3级数据无法按时传输，需暂存于星上缓冲区：

**暂存管理**：
- 星上设置专用遥测缓冲区（建议容量=最长降级持续时间×P1-P3平均帧大小，典型需求约1-10MB）；
- P1/P2/P3数据压缩后（使用对应等级的压缩算法）存入循环缓冲区，FIFO原则，满时旧数据被覆盖（P3数据最先被覆盖，P1数据最后被覆盖）；
- 每帧缓冲数据携带原始时间戳，以便地面还原时序。

**弧段富余补传**：
当信道质量恢复至Q3（高仰角，富余带宽最大）时，在P0-P3当前帧正常传输后，利用剩余带宽以先进先出（FIFO）顺序将缓冲区数据批量补传至地面。补传数据以专用APID（如APID=0x210）标识，地面接收后按原始时间戳重建遥测时序。

**补传优先级**：缓冲区中，优先补传P1数据（最重要），其次P2，最后P3。

**（五）调度结果的遥测下传通知**

星上调度引擎在每帧遥测帧的辅助字段中携带调度状态信息：
- 当前信道质量等级（2位）；
- 各优先级当前实际帧率（各2位）；
- 缓冲区占用率（8位，0-100%）；
- 最近一次压缩等级切换原因（4位枚举）。

地面接收此信息后，可实时监控调度系统运行状态，并在必要时通过TC命令手动调整调度参数（如临时提升某P2参数至P1级）。

### 3. 技术方案基础上的改进与变形

**（1）基于机器学习的调度策略优化**

基础方案采用固定调度矩阵。改进方案中，可使用强化学习（如Deep Q-Network）离线训练调度策略，基于历史弧段的信道质量变化规律和遥测重要性数据，学习最优的动态调度策略。训练后的轻量级策略网络（<10KB参数）部署于星上，实现更精细的自适应调度。

**（2）地面运控主动参与的协同调度**

改进方案中，地面运控软件接收星上调度状态后，若判断某关键参数的帧率已降至不可接受水平（如P1级频繁降为0.5Hz超过10分钟），可通过TC命令发送PACT_PRIORITY_OVERRIDE命令，临时将特定参数提升至P0级，确保不遗漏关键事件。

**（3）多星组网的协同传输调度**

对于星座卫星，当某颗卫星进入低信道质量区域时，若星间链路可用，可将低优先级遥测数据通过星间链路转发至信道质量良好的邻星，再由邻星代传至地面，实现组网协同调度，消除单星测控覆盖盲区对遥测数据完整性的影响。

**（4）基于业务阶段的预定义调度模板**

针对不同任务阶段（发射段、近地点变轨段、正常运行段、载荷工作段、轨道机动段、应急处置段），预定义对应的PACT调度模板。载荷开机时，自动切换至"载荷工作调度模板"（载荷相关参数提升优先级）；轨道机动时，自动切换至"机动调度模板"（推力器和姿控参数提升至P0）。调度模板可通过TC上行在轨修改。

**（5）缓冲区溢出保护策略**

当缓冲区满时，基础方案简单覆盖最老的P3数据。改进方案中，增加基于帧内容的智能覆盖策略：对于缓冲区中同一参数的连续帧，仅保留变化较大的帧（通过比较相邻帧残差），丢弃变化极小的冗余帧，提升缓冲区的信息密度，减少有效数据的丢失。

### 4. 有益效果

**有益效果：**

（1）**保障关键参数全时全量传输**：P0级参数在任何信道条件下以全量无压缩方式传输，确保最关键的安全监测数据不受信道质量影响，从根本上提升卫星在轨安全性。

（2）**动态利用富余带宽最大化遥测数据量**：Q3优良信道状态下，PACT方案充分利用额外带宽同时传输P0-P3全部数据并补传历史缓存，实现遥测数据完整性最大化；典型低轨弧段（仰角10°-85°变化）可使遥测数据收集完整率从传统方案的约70%提升至>95%。

（3）**信道恶化时的优雅降级**：信道质量按Q3→Q2→Q1→Q0分级降级，每级降级只影响对应的低优先级数据，最高优先级数据始终不受影响，系统行为可预测、可管控。

（4）**星上缓存与补传消除数据丢失**：低优先级数据暂存于星上缓冲区并利用弧段富余带宽补传，相比传统方案（信道受限时数据直接丢失），可显著提升P2/P3级遥测数据的完整率。

（5）**调度状态实时可观可控**：通过在TM帧中携带调度状态信息，地面运控人员可实时掌握星上调度系统运行情况，并通过TC命令进行干预，实现人机协同的自适应遥测管理。

（6）**与现有星务软件的低耦合集成**：PACT调度引擎作为遥测处理软件的独立模块实现，对下层CCSDS协议栈和上层参数采集软件透明，工程集成风险低，可作为软件升级包在轨注入现有卫星。

## 六、具体实施方式

**具体实施方案如下：**

以某低轨遥感卫星在轨测控场景为例，卫星下行链路S波段4kbps：

**参数分配情况**：

| 优先级 | 参数数量 | 单帧数据量（压缩前） | 帧率 |
|---|---|---|---|
| P0 | 16个 | 32字节 | 1Hz |
| P1 | 48个 | 192字节 | 1Hz |
| P2 | 96个 | 384字节 | 1Hz |
| P3 | 128个 | 512字节 | 0.5Hz |

未压缩总带宽：(32+192+384+512×0.5) × 8bps = (32+192+384+256)×8 = 6912 bps > 4000 bps（超出容量）

**PACT调度效果**（Q2信道，4kbps）：

| 优先级 | 压缩算法 | 压缩后数据量 | 传输帧率 | 实际带宽占用 |
|---|---|---|---|---|
| P0 | 无压缩 | 32字节 | 1Hz | 256 bps |
| P1 | PVLC轻压 | 192×0.25≈48字节 | 1Hz | 384 bps |
| P2 | PVLC中压 | 384×0.12≈46字节 | 0.5Hz | 184 bps |
| P3 | PDC-OM深压 | 512×0.07≈36字节 | 0.25Hz | 72 bps |
| 帧开销 | CCSDS头部 | ≈30字节/帧 | 2Hz（P0+P1） | 240 bps |
| **合计** | | | | **≈1136 bps** |

实际利用率：1136/4000 = 28.4%（富余带宽约2864bps可用于P3补传或扩充P3帧率）

在Q2信道中，通过PACT调度，所有P0-P3参数均可正常传输，还有大量富余带宽可用于提升P3传输频率或缓存数据补传，充分体现了PACT方法的高效性。

## 七、技术创新点概括

本方案重点要保护如下几方面的创新点：

1）**四级优先级遥测参数分类体系（P0-P3）**：首次提出面向卫星遥测安全管理的四级参数优先级定义（实时关键/重要监测/常规监测/慢遥归档），及每级参数的传输保障要求设计。

2）**P×Q双维度自适应调度矩阵**：将参数优先级（P0-P3）和信道质量等级（Q0-Q3）组合为4×4调度矩阵，矩阵每个元素定义对应场景下的压缩算法和帧率的综合传输策略，这是一种创新的双维度自适应调度设计。

3）**基于星上TC帧接收质量的下行信道质量代理估计方法**：利用TC帧同步字锁定状态和CRC错误率作为下行信道质量的代理指标，在星上无下行链路质量直接测量能力时的工程可行方案。

4）**低优先级数据星上暂存+弧段富余带宽补传机制**：包括循环缓冲区管理、智能覆盖策略、补传时序排序和地面时序重建的完整数据保全机制设计。

5）**基于业务阶段的预定义PACT调度模板系统**：针对不同任务阶段预定义调度策略模板、模板自动切换触发机制，及通过TC命令在轨修改模板的设计。
