## 一、发明/实用新型名称

**名称：一种面向CCSDS空间包协议的卫星遥测三状态增量头部压缩方法**

---

## 二、所属技术领域

本发明涉及卫星通信与航天数据系统技术领域，特别是涉及一种基于状态机和上下文维护的CCSDS（Consultative Committee for Space Data Systems，空间数据系统咨询委员会）空间包协议头部增量压缩方法，通过对CCSDS空间包主头部和辅助头部中不变字段的上下文化处理，实现遥测头部数据的高效压缩，同时保障压缩传输的可靠性与鲁棒性。

---

## 三、现有技术（背景技术）

**背景技术：**

CCSDS空间包协议（CCSDS 133.0-B，Space Packet Protocol）是国际主流卫星遥测数据封装标准，被NASA、ESA、JAXA等主要航天机构广泛采用。空间包由主头部（6字节）和可选辅助头部（最多65530字节，但通常为数至数十字节）以及用户数据域构成。对于典型的遥测应用，主头部占比虽仅6字节，但当单个遥测参数包长度较短（如8-16字节）时，6字节固定主头占总包长的37.5%-75%，头部开销极为显著。

**CCSDS空间包主头部格式（6字节）：**

```
位偏移  字段名               位宽   说明
──────────────────────────────────────────────────────────
0-2     版本号(CCSDS Version) 3 bit  固定=0b000
3       包类型(Pkt Type)       1 bit  0=遥测,1=遥控（固定）
4       辅助头标志(Sec Hdr)    1 bit  0/1（通常固定）
5-15    APID                  11 bit 应用进程标识符（固定）
16-17   分组标志(Grouping)     2 bit  通常固定=0b11（独立包）
18-31   包序列计数(Seq Count)  14 bit 每帧+1，循环递增
32-47   包数据长度(Data Len)   16 bit 用户数据域长度-1（可变或固定）
──────────────────────────────────────────────────────────
```

**现有技术不足：**

**1. CCSDS标准体系无头部压缩机制**

CCSDS体系中，CCSDS 121.0-B定义的数据压缩针对用户数据内容，不处理空间包头部。CCSDS 133.0-B本身无压缩机制。在大量小包传输场景（如高频遥测参数独立打包）中，头部冗余问题尤为突出。

**2. 移动通信领域ROHC协议不可直接适用**

3GPP定义的ROHC（Robust Header Compression，RFC 5795）专门针对IP/UDP/RTP多层协议头，其Profile定义与TCP/IP协议结构深度绑定，不能直接应用于CCSDS空间包头部。此外，ROHC依赖IP层的反馈路由机制传递压缩反馈，而卫星遥测链路为单向传输（无即时反馈），ROHC的反馈依赖机制不适用。

**3. 空间包序列号的周期递增特性未被利用**

包序列计数（Seq Count）每帧严格递增（模16384循环），相邻帧差值固定为1（正常情况下），这一强规律性特征理论上可压缩至0位（仅在异常时传输完整值），现有协议完全未利用此特性。

**4. 时间码冗余问题**

CCSDS二级头部通常携带时间码（CCSDS 301.0-B标准时间码，4-8字节）。由于遥测帧以固定周期采样（如1次/秒、8次/秒等），相邻帧时间戳差值固定，同样具有高度可压缩性，但现有标准未予处理。

综上，现有技术在CCSDS空间包头部存在大量可压缩的冗余信息，缺乏面向卫星遥测特点的头部增量压缩方法，是限制遥测信道有效载荷率的重要因素之一。

## 四、发明/实用新型内容

### 1. 要解决的技术问题

本发明要解决的核心技术问题是：CCSDS空间包协议头部中大量字段在相邻遥测帧间保持不变或具有强规律性（序列号+1递增、时间戳固定步进），导致头部存在大量可压缩冗余，而现有CCSDS标准体系缺乏利用这些特性的头部压缩机制。

具体子问题：

（1）如何设计基于状态机的三状态压缩模式，针对不同阶段（上下文建立、正常压缩、极简压缩）选择最优头部表示方式；

（2）如何处理包序列号的周期性增量特性以及非正常情况（帧丢失、重传）；

（3）如何对CCSDS时间码进行高效的分层增量压缩；

（4）如何在遥测单向传输（无即时反馈）场景下保障压缩可靠性。

### 2. 为解决技术问题而采用的技术方案

**技术方案描述：**

本发明提出一种面向CCSDS空间包协议的三状态增量头部压缩方法（CCSDS-HCP，CCSDS Header Compression Protocol）。该方法借鉴ROHC的状态机思想，针对CCSDS空间包头部特点进行专项设计，定义三种压缩状态，每种状态对应不同粒度的头部表示，通过上下文（Context）机制避免重复传输不变字段。

**（一）核心概念定义**

**上下文（Context）**：星地双方各自维护的一份CCSDS空间包头部字段缓存，记录最近一次FC状态帧中各头部字段的值。同一APID流对应同一个上下文。

**上下文ID（CID，Context Identifier）**：4位（0-15），标识当前压缩流对应的上下文编号，允许最多16个并行遥测流同时压缩。

**（二）三种压缩状态**

**状态1：FC（Full Context，全量上下文）状态**

适用时机：协议初始化阶段、检测到上下文丢失后恢复阶段、每N_refresh帧强制刷新（默认N_refresh=1000帧）。

FC状态帧格式（发送完整头部信息）：

```
字节偏移  字段                位宽    内容
──────────────────────────────────────────────────────────
0         帧类型标识          2 bit   0b11（FC标识）
0         CID                 4 bit   上下文编号(0-15)
0-1       保留                2 bit   全0
1-6       CCSDS主头部         48 bit  完整6字节主头（原样携带）
7-N       CCSDS辅助头         可变    完整辅助头（原样携带）
N+1       辅助头长度          8 bit   辅助头字节数（0=无辅助头）
N+2-N+3   CRC校验             16 bit  覆盖FC帧内容
──────────────────────────────────────────────────────────
总开销增加：3字节（CID字节+辅助头长度+CRC，相对原头部）
```

收到FC帧后，接收端更新对应CID的上下文（记录所有头部字段值），后续SC/MC帧可据此还原。

**状态2：SC（Shared Context，共享上下文）状态**

适用时机：上下文建立后的正常运行阶段，包序列号连续（无丢帧）。

SC状态帧格式（传输增量信息）：

```
字节偏移  字段                位宽    内容
──────────────────────────────────────────────────────────
0         帧类型标识          2 bit   0b10（SC标识）
0         CID                 4 bit   上下文编号
0         标志位组            2 bit   bit1: SeqDelta≠1标志（跳帧/重传）
                                      bit0: 辅助头时间戳变化标志
1-2       SeqDelta            0或16bit 若SeqDelta=1，此字段省略（0字节）；
                                       若SeqDelta≠1，携带完整14位序列号
                                       （含2位填充），16 bit
[可选]2-3 TimeDelta           16 bit  时间戳与标准步进值之差（毫秒），
                                      仅当时间戳变化标志=1时携带
[必须]2字节 CRC               16 bit  覆盖SC帧
──────────────────────────────────────────────────────────
正常情况（SeqDelta=1，时间戳正常步进）：
原始头部：6字节主头 + 8字节辅助头（时间码）= 14字节
SC压缩帧：1字节（CID+标志）+ 2字节CRC = 3字节
压缩率：(14-3)/14 × 100% ≈ 78.6%
```

**状态3：MC（Minimum Context，最小上下文）状态**

适用时机：在SC状态下运行稳定超过M_stable帧（默认M_stable=50帧）后，自动进入MC状态。

MC状态帧格式（极简表示）：

```
字节偏移  字段                位宽    内容
──────────────────────────────────────────────────────────
0         1字节标识帧         8 bit   高2位=0b01（MC标识）
                                      低4位=CID
                                      bit2=序列号异常标志（通常=0）
[可选]    异常数据            可变    仅在序列号异常时携带
──────────────────────────────────────────────────────────
正常情况：
原始头部：14字节
MC压缩帧：1字节（CID+类型标识）
压缩率：(14-1)/14 × 100% ≈ 92.9%
```

**（三）状态转移条件**

```
状态转移规则：

FC → SC：发送FC帧后，若下一帧序列号连续（SeqDelta=1），切换至SC；
SC → MC：在SC状态连续正常运行M_stable帧后，自动切换至MC；
MC → SC：接收端通过TC反馈（或星上主动检测）发现SeqDelta≠1，
         下一帧切换至SC（携带完整序列号）；
SC/MC → FC：以下任一情况触发：
         ①检测到CID对应上下文可能已失效；
         ②累计发送N_refresh帧（强制刷新）；
         ③接收到TC上行的RESYNC请求；
         ④SeqDelta超过阈值（如>10，说明严重丢帧）。
```

**（四）时间码分层压缩方法**

CCSDS辅助头时间码（基于CCSDS 301.0-B，典型格式：4字节粗时间+2字节精时间=6字节）的分层压缩：

- **粗时间（秒级，4字节）**：以固定采样周期T_s（如1秒、0.125秒）递增，相邻帧差值固定为T_s。在FC帧中传输完整4字节，在SC/MC帧中仅在实际步进值偏离T_s时（如星上时钟漂移）传输偏差量（16位有符号毫秒偏差），正常情况下不传输（隐式递增T_s）；

- **精时间（亚秒级，2字节）**：若遥测采样在固定相位触发，相邻帧亚秒时间固定不变；在FC帧传输完整2字节，在SC/MC帧中不传输（上下文复用）。

此分层方法可将6字节时间码在正常情况下压缩为0字节（完全由上下文推算），仅在异常时传输差分修正量。

**（五）CID分配与管理**

- CID 0：保留，用于广播FC帧（刷新所有上下文）；
- CID 1-14：按APID分配，每个需压缩的遥测流分配一个CID；
- CID 15：保留，用于控制/维护帧；
- CID与APID的映射关系在三阶段协商（参见本系列专利2）时确定，存储于星地两端的上下文映射表中。

### 3. 技术方案基础上的改进与变形

**（1）可扩展CID位宽**

基础方案采用4位CID（支持16并行流）。对于大型卫星平台（有效载荷多、APID数量大），可扩展为8位CID（支持256并行流），通过FC帧头部的扩展标志位区分4位/8位CID模式。

**（2）辅助头的选择性压缩**

基础方案对整个辅助头进行压缩（时间码外的字段视为不变，在FC帧传输）。改进方案中，可对辅助头中的可变字段（如子帧计数器、辅助数据指针等）单独定义变化标志位，进行更精细的字段级压缩。

**（3）基于前向纠错（FEC）的鲁棒压缩**

在信道误码率较高的场景（如月球/火星探测），可在CCSDS-HCP压缩流中周期性插入"上下文刷新帧"（即FC帧），刷新周期与信道误码率自适应关联：BER越高，刷新越频繁（N_refresh越小），以降低错误传播范围，提升鲁棒性。

**（4）与PVLC协议的联合压缩**

CCSDS-HCP负责压缩CCSDS空间包头部，PVLC（专利1）负责压缩用户数据域中的遥测参数值。两者可同时使用，形成端到端的完整压缩方案，CCSDS-HCP压缩后的帧作为外层，其用户数据由PVLC进一步压缩，实现头部+数据的双重压缩。

**（5）MC状态快速失效检测**

为防止MC状态因上下文悄然失效而导致持续错误，在每发送K个MC帧后（默认K=20），强制插入一帧SC帧（携带序列号以供核实），若SC帧解析正确则继续MC状态，否则触发FC重建。

### 4. 有益效果

**有益效果：**

（1）**显著降低遥测包头开销**：三状态压缩方案中，MC状态下头部从14字节压缩至1字节（压缩率≈93%），SC状态下从14字节压缩至3字节（压缩率≈79%）。对于小数据量遥测包（如16字节短包），有效载荷率从57%提升至94%，显著提升信道利用率。

（2）**完全兼容CCSDS标准**：CCSDS-HCP压缩帧嵌入CCSDS TM数据链路帧的虚拟信道用户数据域中，不修改CCSDS空间包协议本身，对星地接口透明，工程适应性强。

（3）**利用遥测序列号固有规律**：将序列号的严格递增特性（SeqDelta=1）转化为零开销传输，充分利用了卫星遥测数据的独有规律性，是对现有压缩方法的重要补充。

（4）**时间码分层压缩消除时戳冗余**：周期采样的固定时间步进特性使时间码在正常情况下可以零字节传输，对于每帧携带CCSDS时间码（4-8字节）的遥测系统，节省效果尤为显著。

（5）**三状态渐进压缩保障鲁棒性**：FC→SC→MC的渐进压缩策略确保上下文建立阶段的可靠性，同时允许稳定运行阶段达到最高压缩率；强制刷新机制（N_refresh）限制了上下文失步的最大影响范围。

（6）**支持多路并行压缩流**：CID机制允许同时压缩最多15个不同APID的遥测流，适应多载荷、多子系统并发遥测的实际需求。

## 六、具体实施方式

**具体实施方案如下：**

以某卫星遥测系统中，高频遥测（4Hz采样，每帧8个参数）的头部压缩为例：

**参数设定**：
- CCSDS空间包：APID=0x050（热控遥测），辅助头携带CCSDS时间码（6字节），用户数据16字节，总包长=6+6+16=28字节；
- CID分配：CID=2分配给APID=0x050；
- 采样周期T_s=250ms（4Hz），时间步进固定。

**实施步骤一：上下文建立（FC状态）**

遥测压缩模块发送FC帧：将完整28字节空间包头部（6字节主头+6字节辅助头+已记录用户数据长度）写入FC帧，附加1字节CID/类型标识和2字节CRC，共31字节（vs原始28字节，FC阶段略有开销，换取后续大幅压缩）。地面接收并记录上下文：APID=0x050, SeqCount=2301, 时间戳=T₀, DataLen=0x000F(15)。

**实施步骤二：切换至SC状态**

下一帧（SeqCount=2302）满足SeqDelta=1，时间步进=250ms（正常），切换至SC模式：发送SC帧= [0b10_0010_00][CRC_HIGH][CRC_LOW] = 3字节。地面解压：SeqCount=2301+1=2302, 时间戳=T₀+250ms, 其余字段从上下文复用 → 还原完整28字节包头。

**实施步骤三：切换至MC状态（50帧后）**

连续50帧SC帧正常传输后（无跳帧），切换至MC模式：发送MC帧= [0b01_0010_000] = 1字节。地面解压：SeqCount自增1, 时间戳自增250ms, 其余字段上下文复用。

**实施步骤四：异常处理（帧丢失）**

某时刻，由于瞬时遮挡，地面连续丢失3帧MC帧（序列号2500-2502）。地面检测到序列号跳变（收到2503），发送TC RESYNC请求，星上立即发送FC帧（序列号2504），地面接收FC帧后重建上下文，从2505帧起重新以SC/MC模式正常接收。

**实施步骤五：压缩效益统计**

运行1小时（4Hz×3600s=14400帧），其中FC帧2帧（初始+1次刷新），SC帧150帧，MC帧14248帧：
- 未压缩总字节：14400×14 = 201600 字节（仅计头部）；
- 压缩后总字节：2×17 + 150×3 + 14248×1 = 34+450+14248 = 14732 字节；
- 头部压缩率：(201600-14732)/201600 × 100% ≈ 92.7%。

## 七、技术创新点概括

本方案重点要保护如下几方面的创新点：

1）**面向CCSDS空间包头部特点的三状态压缩状态机设计**：FC/SC/MC三状态及其转移条件的完整状态机设计，这是首个专门针对CCSDS空间包头部的增量压缩协议。

2）**利用遥测序列号严格递增特性的零位压缩方法**：将SeqDelta=1这一遥测序列号的固有规律转化为零传输开销，以及SeqDelta≠1时的完整值回退机制。

3）**CCSDS时间码的周期采样分层压缩方法**：基于固定采样周期的时间戳零字节传输方法，及时间戳偏差的差分修正传输方案。

4）**基于CID的多APID并行压缩流管理机制**：CID分配、映射与管理方法，支持同一TM链路上多个并行遥测流的独立压缩上下文维护。

5）**自适应FC刷新周期与BER关联的鲁棒压缩机制**：FC强制刷新周期N_refresh与信道BER动态关联的方法，在保障鲁棒性的前提下最大化压缩率。
