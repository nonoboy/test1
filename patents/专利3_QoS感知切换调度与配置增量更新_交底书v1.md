## 一、发明名称

**一种5G NTN干扰规避场景下QoS感知用户切换调度与配置增量更新方法**

---

## 二、技术领域

本申请提案的技术方案属于**无线通信**领域，具体涉及**卫星通信**和**物联网**子领域。

本申请提案针对5G NTN再生载荷LEO卫星场景，解决干扰规避触发业务波束关断时，如何按用户业务优先级有序完成用户切换（保障高价值业务连续性）以及如何高效更新干扰规避配置信息（降低S-C1接口传输开销）两个工程实践问题，并提出含QoS约束的增强版有效覆盖时间刷新算法以优化切换目标选择质量。

---

## 三、现有技术的技术方案

### 3.1 公知技术背景

**5G NTN卫星切换**：3GPP TR 38.821及相关规范定义了LEO卫星场景下的切换流程，包括星内切换（同一卫星不同波束间）和星间切换（不同LEO卫星间）。切换决策的主要依据是参考信号接收质量（RSRQ/RSRP）测量值和**覆盖时间（Coverage Duration）**预测。对于LEO卫星，覆盖时间是指从当前时刻到卫星飞出UE覆盖范围的剩余时间，是切换目标选择的重要参数。

**5QI与QoS等级**：3GPP TS 23.501定义了5G QoS标识符（5QI）体系，将数据无线承载（DRB）按业务类型（语音、视频、数据等）、时延需求（延迟预算）和优先级（资源调度优先级）分类。其中GBR（保证比特率）承载（如5QI=1语音、5QI=2视频会议）须保证最低比特率；Non-GBR承载（如5QI=9后台数据）无最低比特率保证，业务中断相对可接受。

**S-C1接口可靠传输机制**：现有方案中，SCF向S-gNB下发干扰规避配置信息时，采用全量Bitmap发送方式——即使少量波位的规避状态发生变化，也需重传包含所有波位状态的完整Bitmap。分包传输机制（每包建议间隔10~50 ms，每350包批量确认）保证了可靠交付，但无增量更新机制。

**覆盖时间刷新算法（原有版本）**：原方案提出从原始覆盖时间段[A1,A2]中剔除干扰规避时段，得到若干不连续有效覆盖子段，选取最长子段[T1,T2]作为刷新后的有效覆盖时间用于切换决策。该算法无QoS约束，对所有UE统一处理。

### 3.2 最接近的现有技术方案

**现有技术A（3GPP标准NTN切换方案）**：S-gNB在业务波束干扰规避开始前，对该波位的所有在网UE发起切换，以避免规避时段内业务中断。特征：
- **UE处理顺序**：无优先级区分，按UE接入顺序或系统内部排序统一触发切换，未考虑各UE的业务类型（GBR/Non-GBR）和QoS等级；
- **目标选择**：基于RSRQ和覆盖时间（含干扰规避时段剔除），选择覆盖时间最长的波位作为切换目标，未引入目标波位剩余容量约束；
- **GBR承载处理**：无专项保障机制，GBR承载的切换优先级与Non-GBR承载相同，在资源受限场景下可能因目标波位容量不足而切换失败，导致GBR承载中断。

**现有技术B（Bitmap全量更新方案）**：每次干扰规避配置变更（含星历修正、IRL等级调整等），SCF均发送全套Bitmap配置信息（64字节/波位/层，固定开销），无论变化的波位数量多少。在星座多卫星同时运行、配置更新频繁的场景下，S-C1链路带宽压力大，更新时延长，配置灵活性受限。

## 四、现有技术的缺点及本申请提案要解决的技术问题

### 4.1 现有技术缺点

**缺点一：切换无优先级，高价值业务中断风险高**

现有技术A对所有UE统一执行切换，在PAW（规避前预处理窗口）时间有限（通常1~3秒）且目标波位资源有限的情况下，若切换队列较长，后处理的UE可能因规避窗口已开始而无法完成切换，导致业务中断。由于没有优先级机制，中断发生的用户随机，可能使紧急通信、实时语音等高价值GBR业务因排队等待而中断，而后台数据下载等低价值业务则可能被优先处理。

**缺点二：未考虑目标波位容量约束，切换目标选择可靠性差**

现有技术A仅依据RSRQ测量值和覆盖时间选择切换目标，未考虑目标波位的当前已用容量。若选定的目标波位已接近满载，新切入的UE（特别是GBR承载UE）可能无法获得所需资源，导致GBR承载降级或切换失败，即便RSRQ和覆盖时间满足要求，实际业务质量也无法保证。

**缺点三：覆盖时间刷新算法无QoS感知，切换目标次优**

原有覆盖时间刷新算法对所有UE使用相同的"最长连续时段优选"策略。对于GBR业务UE，一个连续覆盖时间较长但碎片化（被多个规避时段切割）的波位，可能比时间总量稍少但连续性更好的波位更差，但原有算法会优选前者，导致GBR承载频繁切换（切换乒乓效应）。

**缺点四：配置全量更新传输开销大，配置实时性受限**

现有技术B全量Bitmap更新在少量波位变化的场景下（典型星历修正仅影响<5%的波位），仍需传输全套配置数据，在多卫星并发配置更新场景下，S-C1链路带宽成为瓶颈，限制了配置更新的频率和实时性。

### 4.2 本申请提案要解决的技术问题

1. 如何在干扰规避触发切换场景下，按UE的QoS等级（5QI/GBR属性）建立优先级切换队列，保障高价值业务优先完成切换；
2. 如何在切换目标选择时引入目标波位剩余容量约束，提升GBR承载的切换成功率；
3. 如何为GBR和Non-GBR业务分别设计有效覆盖时间刷新策略，减少切换乒乓效应；
4. 如何设计增量差分Bitmap（Delta-Bitmap）更新机制，大幅降低配置更新的传输开销。

## 五、本申请提案的技术方案的详细阐述

### 技术方案一：QoS感知优先级切换调度（S-gNB-QAS）

#### 5.1.1 QAS模块位置与触发条件

QoS感知切换调度器（QAS）集成于S-gNB的L3（RRC）层，负责管理干扰规避场景下的用户切换调度。触发条件：SCF下发业务波束干扰规避配置信息，指定某波位将在时刻 start 开始规避（IRL-3完全关断），且当前时刻距 start 的剩余时间 T_remain ≤ PAW_max（规避前预处理窗口最大长度，默认5秒，由SCF在配置信息中指定）。

#### 5.1.2 UE四级优先级分类规则

QAS将该规避波位下的所有在网UE按以下规则分为四个优先级（P1最高，P4最低）：

| 优先级 | 判定条件 | 业务类型示例 | 切换策略 |
|-------|---------|-----------|---------|
| P1（紧急） | 5QI ∈ {65,66,69,70}（任务关键/紧急通信）或运营商显式标记（Emergency_Flag=1） | MCPTT（集群通话）、公共安全视频、急救通话 | 立即触发，PAW开始后第一批处理，优先抢占目标波位预留资源 |
| P2（实时GBR） | GBR > 0 且 5QI ∈ {1,2,3,4}（其他实时GBR业务） | VoNR语音、视频会议、实时游戏 | PAW前2/3时间内必须完成切换；若超时仍未完成，升级处理力度（增加候选目标数） |
| P3（交互Non-GBR） | GBR = 0 且 5QI ∈ {5,6,7,8,9}（时延敏感Non-GBR） | Web浏览、流媒体、互动应用 | PAW内完成切换（可排在P2之后） |
| P4（后台Non-GBR） | GBR = 0 且 5QI ≥ 65（后台传输类） 或 5QI ∈ {10, 11,…}（尽力而为） | 文件下载、软件更新、邮件同步 | 若PAW剩余时间不足，允许进入"挂起"态（承载挂起，数据缓存），规避结束后自动恢复 |

**判定优先级的数据来源**：QAS从S-gNB的RRC层维护的UE上下文中获取各UE的DRB（数据无线承载）的5QI和GBR参数（这些参数在UE接入或PDU会话建立时由核心网下发）。若一个UE同时持有多种5QI的DRB，则取其最高优先级的DRB对应优先级作为该UE的整体优先级。

#### 5.1.3 切换调度流程

**步骤1：建立优先级切换队列**

QAS在收到规避配置信息后，立即对规避波位的所有在网UE按P1~P4分类，构建切换队列（P1队列 → P2队列 → P3队列 → P4队列）。

**步骤2：PAW时间资源分配**

设PAW总时长为 T_PAW（由SCF配置，默认为3秒），QAS按以下比例为各优先级分配时间资源：
- P1：立即触发（不占用时间配额，具有最高抢占权）；
- P2：分配 T_PAW × 60% 的时间窗完成切换；
- P3：分配 T_PAW × 30% 的时间窗；
- P4：剩余 T_PAW × 10% 时间内若完成则切换，否则执行挂起。

若P1+P2阶段实际用时少于分配时间，剩余时间顺延给P3和P4使用。

**步骤3：P1/P2 UE切换执行**

对P1和P2队列中的每个UE：
1. QAS调用含QoS约束的目标选择算法（见5.1.4节）选定切换目标波位；
2. 发起RRC连接重配置消息（含MobilityControlInfo），完成切换信令交互；
3. 切换完成后，QAS在RRM模块中为该UE的GBR承载预留目标波位的资源（通过资源预留令牌机制）；
4. 若切换失败（RACH竞争失败、目标波位拒绝），QAS对P1/P2 UE自动选择次优目标并重试（最多3次）。

**步骤4：P3 UE切换执行**

同P1/P2流程，但无GBR资源预留，按尽力而为原则切换；若切换失败，允许UE在规避开始时暂时继续在原波位接入（若规避为IRL-2而非IRL-3，则业务可能部分保持）。

**步骤5：P4 UE"挂起+恢复"机制**

若P4队列中有UE在PAW内未能完成切换：
1. S-gNB向UE发送"RRC挂起（RRCRelease with suspendConfig）"消息；
2. UE进入"挂起"（Suspended）态，保留RRC上下文；
3. 干扰规避时段（[start, end]）结束后，S-gNB向挂起UE发送"RRC恢复"触发，UE通过随机接入完成恢复，数据传输继续；
4. 挂起期间，S-gNB保留该UE的缓存数据（支持最大挂起时长 T_suspend_max，默认60秒，超时后释放上下文）。

#### 5.1.4 目标波位容量感知选择（CATS）

QAS在选择切换目标波位时，在覆盖时间刷新算法输出的候选波位集合中，按以下约束进行筛选和排序：

**筛选条件**：
- **RSRQ阈值约束**：目标波位的RSRQ预测值 ≥ RSRQ_min（可配置，默认-12 dB）；
- **有效覆盖时间约束**：刷新后的有效覆盖时间 ≥ ECD_min（针对P1/P2 UE，见5.3节）；
- **容量约束（新增）**：目标波位的剩余容量余量 C_margin ≥ C_required，其中：
  ```
  C_margin = C_total - C_used - C_reserved
  C_required = GBR_i（对P1/P2 GBR承载UE）或 0（对P3/P4 UE）
  ```
  C_reserved 为该波位已为其他待切入UE预留的资源量；

**排序规则**：对满足上述约束的候选波位，按（有效覆盖时间 × 容量余量比）加权降序排列，取排名第一的波位作为切换目标：
```
Score_candidate = w1 × ECD_normalized + w2 × (C_margin / C_total)
```
其中 w1 = 0.7，w2 = 0.3（可配置），ECD_normalized 为有效覆盖时间归一化值。

### 技术方案二：含QoS约束的增强版有效覆盖时间刷新算法

#### 5.2.1 原始算法回顾

输入：原始连续覆盖时间段 [A1, A2]；干扰规避时段集合 {[B1,B2], [C1,C2], …}。
处理：从 [A1, A2] 中逐一剔除与各规避时段重叠的部分。
输出：若干不连续的有效覆盖子段 {[T1_1, T1_2], [T2_1, T2_2], …}，取时长最长的一段作为有效覆盖时间。

#### 5.2.2 增强算法：GBR业务的最短连续覆盖约束

**增强点1：GBR业务引入最短连续覆盖时长约束（GMCC）**

对P1/P2（GBR业务）UE，在执行目标选择时，额外要求候选目标波位的最长连续有效覆盖子段时长 T_max_segment ≥ GMCC：

```
GMCC = max(T_session_remain, GMCC_min)
```

其中 T_session_remain 为当前会话的估计剩余时长（若可知），GMCC_min 为系统配置的最小连续覆盖保证（默认30秒）。

若最长连续子段 T_max_segment < GMCC，则该候选波位不满足P1/P2 UE的目标要求，应从候选集中剔除，避免切换后因频繁遇到规避时段而再次切换（切换乒乓效应）。

**增强点2：Non-GBR业务采用累计有效覆盖时长**

对P3/P4（Non-GBR业务）UE，有效覆盖时间定义为所有有效连续子段的时长之和（累计有效覆盖时长），允许业务在规避时段内短暂中断并在覆盖恢复后继续：

```
ECD_NonGBR = Σ_i (T_i_end - T_i_start)   （所有有效子段时长之和）
```

**增强点3：次优连续段选择策略**

对GBR业务UE，若最长连续子段不满足GMCC，但存在次长连续子段满足GMCC，则优选次长段作为有效覆盖时间参考，而非简单选最长段：

```
PROCEDURE Select_ECD_GBR(Segments, GMCC):
  SORT Segments by duration (descending)
  FOR each segment in sorted order:
    IF segment.duration >= GMCC:
      RETURN segment    ← 返回第一个满足GMCC约束的连续段
  RETURN None           ← 无满足GMCC的段，不选该候选波位
```

**增强点4：干扰规避时段剔除的精度优化**

当规避时段边界与子帧边界不完全对齐时，采用"保守剔除"策略（将规避时段向两侧各扩展0.5 ms），确保剔除后的有效覆盖时间不包含任何规避时段重叠区域，避免误估有效覆盖时间。

### 技术方案三：干扰规避配置信息增量差分Bitmap更新机制

#### 5.3.1 全量与增量更新的适用场景判断

SCF在需要更新已下发的干扰规避配置时，首先评估本次更新的"变化量"（Changed_Count = 发生IRL等级变化的波位数量）：

- 若 Changed_Count ≤ Threshold_Delta（增量更新阈值，默认63，即当变化波位数低于总波位数的约12%时），采用**增量Delta-Bitmap更新**；
- 若 Changed_Count > Threshold_Delta，采用**全量Bitmap更新**（原有方案）；
- SCF将当前生效配置的版本号（RCV，随每次全量更新递增）通知S-gNB，增量更新基于RCV进行。

#### 5.3.2 Delta-Bitmap增量更新命令（DUC）结构设计

Delta-Bitmap增量更新命令（DUC，新增命令类型，建议命令类型码0x0009）的数据包结构如下：

**包头字段**：
- **命令类型（Cmd_Type，8比特）**：0x0009（标识为Delta更新命令）；
- **总包数（Total_PKT，16比特）**和**包索引号（PKT_Index，16比特）**：与全量更新相同的分包机制；
- **基准配置版本号（RCV，32比特）**：本次增量更新所基于的全量配置版本号，S-gNB需校验本地生效的配置版本与RCV一致；
- **新配置版本号（New_Ver，32比特）**：本次更新生效后的配置版本号；
- **变化波位总数（Changed_Count，16比特）**；

**波位变化描述（每个变化波位占用固定4字节）**：
- **波位索引（Beam_Index，16比特）**：发生变化的波位编号（0~N_beam-1）；
- **新IRL等级（New_IRL，2比特）**：该波位更新后的干扰风险等级（00/01/10/11）；
- **新PAA工作模式（New_PAA_Mode，3比特）**：对应的天线工作模式；
- **保留（Reserved，11比特）**：供扩展使用（如未来增加NS方向更新等）；

**传输效率对比**：
- 全量更新（单层Bitmap，512波位）：64字节；
- 三层复合Bitmap全量更新（512波位）：192字节；
- Delta更新（K个波位变化）：6字节（包头固定部分）+ K × 4字节（波位变化描述）；
- 当 K ≤ 47时（约9%波位变化），Delta更新数据量（194字节）≈ 三层Bitmap全量更新（192字节），平衡点；
- 典型星历修正场景（K ≤ 20），Delta更新仅需86字节，相比三层全量更新节省约55%带宽。

#### 5.3.3 S-gNB版本一致性验证与回退机制

**步骤1：版本校验**

S-gNB接收到DUC后，读取RCV字段，与本地当前生效的配置版本号（Local_Ver）比较：
- 若 Local_Ver = RCV：版本一致，执行增量更新，将指定波位的IRL等级和PAA模式更新至本地配置，并将Local_Ver更新为New_Ver；
- 若 Local_Ver ≠ RCV：版本不一致（本地配置可能因之前的包丢失而与SCF期望的基准不同），返回版本不一致错误响应（含Local_Ver信息）。

**步骤2：错误处理与全量回退**

SCF收到版本不一致响应后：
- 分析原因：若Local_Ver < RCV，说明S-gNB漏掉了某次全量更新，SCF立即发送最新全量配置（以New_Ver为版本号）覆盖S-gNB当前配置；
- 若 Local_Ver > RCV（罕见，可能因SCF重启导致），SCF同样发送最新全量配置；
- 全量回退完成后，S-gNB回复确认响应，后续继续使用Delta更新。

**步骤3：S-gNB本地配置镜像维护**

S-gNB维护一份"当前生效配置镜像"（Current_Config_Mirror），存储全部波位的当前IRL等级和PAA模式。每次收到Delta更新后，仅更新Changed_Count个波位的对应字段；全量更新则整体刷新镜像。配置镜像支持快速索引（按波位索引直接访问），Delta更新执行效率高。

#### 5.3.4 增量更新时序与分包机制

- DUC分包传输规则与全量配置相同（建议每包间隔10~50 ms，每350包批量确认）；
- DUC的优先级可设置高于全量配置包（在S-C1链路拥塞时优先传输，因为Delta更新通常是时效性更强的紧急更新）；
- S-gNB在收到全部DUC包并完成版本校验后，原子性地切换配置（即配置切换是整体生效的，不会出现部分波位已更新而其他未更新的中间状态）。

## 六、本申请提案的关键点和欲保护点

按重要性从高到低排列：

1. **干扰规避场景下UE的四级优先级（P1~P4）分类规则**：基于5QI和GBR属性区分紧急通信、实时GBR业务、时延敏感Non-GBR业务和后台Non-GBR业务，以及对应的PAW内分时段切换调度策略；

2. **P4 UE的"挂起+规避后自动恢复"机制**：PAW时间不足时，QAS向P4 UE发送RRCRelease with suspendConfig，规避结束后主动触发恢复，避免强制切换占用有限资源同时保证业务最终连续性；

3. **目标波位容量感知选择（CATS）算法**：在覆盖时间和RSRQ约束基础上，引入C_margin ≥ C_required的容量余量约束，以及综合有效覆盖时间和容量余量比的加权评分排序；

4. **含GMCC约束的GBR业务增强版有效覆盖时间刷新算法**：要求GBR业务候选目标波位的最长连续有效覆盖子段时长≥GMCC，以及次优连续段优先选择策略（Select_ECD_GBR过程）；

5. **Non-GBR业务累计有效覆盖时长计算方式**：允许多段不连续覆盖累计统计，与GBR业务差异化处理；

6. **Delta-Bitmap增量更新命令（DUC）数据结构设计**：含RCV、New_Ver、Changed_Count、Beam_Index、New_IRL、New_PAA_Mode等字段的4字节/波位编码格式；

7. **版本一致性验证与全量回退机制**：S-gNB维护Local_Ver校验RCV，不一致时自动触发SCF全量配置回退，确保增量更新的正确性；

8. **增量vs全量更新阈值决策（Threshold_Delta）**：SCF根据Changed_Count与Threshold_Delta比较，自动选择最优更新策略。

## 七、与现有技术相比，本申请提案有何技术优点

**优点一：高价值业务连续性大幅提升**
现有技术切换无优先级，高价值GBR业务中断概率与普通用户相同。本方案P1/P2优先级保障机制确保紧急通信和实时语音/视频业务在PAW内优先完成切换，同时通过容量感知选择避免因目标波位满载导致的切换失败。P1/P2切换成功率可由无保障提升至98%以上（典型负载场景下估算值）。

**优点二：系统整体资源利用率提升，避免资源浪费**
P4业务的"挂起+恢复"机制替代了强制切换，在规避时段短（<60秒）的场景下，避免了P4业务切换占用目标波位资源（切换后规避很快结束又切回），减少了不必要的切换信令开销，提升资源利用率。

**优点三：GBR业务切换乒乓效应显著减少**
引入GMCC约束后，切换目标选择会优先保证连续覆盖质量而非仅看覆盖总量，避免了选择覆盖时间分散（多次被规避时段打断）的目标波位导致的二次切换，减少GBR业务切换次数约30%（与无GMCC约束方案对比的理论估算）。

**优点四：配置更新传输效率显著提升**
对于典型的星历修正场景（变化波位K≤20），Delta-Bitmap更新将传输数据量从192字节（三层全量Bitmap）降至约86字节，减少约55%；在星座多卫星并发更新场景下，S-C1链路聚合带宽需求大幅降低，使配置更新频率可提升2~3倍，增强了干扰规避配置对星历变化的响应实时性。

**优点五：配置更新正确性有机制保障**
版本一致性验证机制防止了增量更新在配置版本不一致时静默出错（即S-gNB用错误的基准配置执行增量更新），通过自动回退到全量配置，保证了系统配置的最终一致性，增强了系统鲁棒性。

## 八、发散思维以及规避方案思考

**规避方向一（简化为两级优先级）**：使用者可能仅区分GBR和Non-GBR两级（而非P1~P4四级），同样实现优先级切换。
*建议*：主权利要求保护"根据UE业务类型和/或QoS参数，建立多级（≥2级）切换优先级队列"的通用框架；P1~P4四级分类在从属权利中保护。

**规避方向二（不用"挂起"而用"暂停调度"）**：使用者可能不通过RRC挂起实现P4 UE的暂停，而是在MAC层暂停对P4 UE的调度（不发RRC消息给UE），规避结束后恢复调度。
*建议*：权利要求表述"对低优先级UE执行服务暂停（包括RRC挂起、MAC层调度暂停或其他暂停形式），并在规避结束后恢复服务"，覆盖不同实现形式。

**规避方向三（不用Delta-Bitmap，用差分编码的索引列表）**：使用者使用波束索引差分列表（将索引排序后编码相邻索引差值），实现同样的增量更新效果。
*建议*：主权利要求保护"仅传输发生规避状态变化的波位标识及其新状态，而不传输全部波位状态"的增量更新本质，具体编码格式在从属权利中保护。

**规避方向四（GMCC约束由UE自主决定）**：使用者在UE侧实现切换拒绝逻辑（若目标波位连续覆盖不满足GMCC，UE拒绝切换），而非在S-gNB侧过滤。
*建议*：权利要求中将GMCC约束描述为"由网络侧节点（S-gNB）或终端侧（UE）执行的、对切换目标连续覆盖质量的约束"，覆盖两种执行位置。
