## 一、发明/实用新型名称

**一种5G NTN干扰规避场景下QoS感知用户切换调度与配置增量更新方法**

---

## 二、所属技术领域

本发明涉及卫星通信技术领域，特别是涉及一种在5G NTN（非地面网络）低轨（LEO）卫星通信系统中，当干扰规避导致业务波束关断时，依据用户的服务质量（QoS）等级进行分优先级切换调度的方法，以及干扰规避配置信息的增量差分更新方法。

## 三、现有技术（背景技术）

### 背景技术

**5G NTN切换机制**：在3GPP Release 17及后续版本定义的NTN再生载荷架构中，星上基站（S-gNB）负责管理地面用户设备（UE）的无线接入和切换。当业务波束因干扰规避需要在时刻start完全关断时，S-gNB须在start之前完成对该波位上所有在网UE的切换，以避免业务中断。3GPP TS 23.501定义了5QI（5G QoS标识符）体系，将数据无线承载按业务类型分类：GBR（保证比特率）承载（如5QI=1语音、5QI=2视频会议）须保证最低比特率；Non-GBR（非保证比特率）承载（如5QI=9后台数据）对中断相对容忍。

**配置信息传输机制**：地面卫星控制设备（SCF）通过S-C1接口向S-gNB分包上注干扰规避配置信息，目前采用全量发送方式：每次更新均发送包含全部波位状态的完整位图（Bitmap）。对于随遇波束的三层复合Bitmap（A-Bitmap + NS-Bitmap + SL-Bitmap），全量发送约192字节/次，无论实际变化的波位数量多少。

**覆盖时间刷新算法（原有版本）**：原有方案从原始覆盖时间段[A1, A2]中剔除干扰规避时段，取最长连续有效子段[T1, T2]作为有效覆盖时间，用于切换目标选择，对所有UE统一处理，无QoS感知。

**现有最接近技术方案的缺点**：

1. 切换无优先级区分：S-gNB对规避波位所有UE统一触发切换，未考虑业务QoS等级，在切换资源有限的场景下，高价值GBR业务（语音、视频）可能因排队等待而在规避开始时仍未完成切换，导致中断；

2. 切换目标选择未考虑目标波位的剩余容量：即使覆盖时间满足要求，若目标波位已近满载，新切入的GBR承载UE无法获得所需资源，切换失败率偏高；

3. 覆盖时间刷新算法无QoS约束：对GBR业务UE，仅以总覆盖时长为依据可能选中覆盖时间碎片化的目标波位，导致切换后不久再次被规避时段打断，产生切换乒乓效应；

4. 配置全量更新传输开销大：在少量波位规避状态变化（如仅10~20个波位的IRL等级更新）的场景下，仍需重传全套192字节Bitmap，在多星并发管理场景下S-C1链路带宽压力大，配置更新时延长。

## 四、发明/实用新型内容

### 1、要解决的技术问题

本发明要解决的技术问题是：

（1）如何在干扰规避触发切换场景下，按UE的5QI/GBR属性建立优先级切换队列，优先保障高价值GBR业务的切换完成，同时避免低价值业务强占切换资源；

（2）如何在切换目标选择中引入目标波位剩余容量约束，提升GBR承载的切换成功率；

（3）如何为GBR和Non-GBR业务分别制定有效覆盖时间刷新策略，减少切换乒乓效应；

（4）如何设计增量差分Bitmap更新机制，在少量波位状态变化时大幅降低S-C1接口传输开销。

### 2、为解决技术问题而采用的技术方案

本发明在S-gNB的RRC层（L3）增加QoS感知切换调度器（QAS，QoS-Aware Switching Scheduler）模块，并在SCF的配置管理模块中增加增量更新决策逻辑，具体技术方案如下：

#### 技术方案一：QoS感知四级优先级切换调度机制

**UE四级优先级分类规则**：

QAS从S-gNB维护的UE上下文中获取各UE的DRB（数据无线承载）5QI和GBR参数，按以下规则分类（一个UE有多种DRB时取最高优先级）：

| 优先级 | 判定条件 | 业务示例 | 切换策略 |
|:---:|------|------|------|
| P1（紧急） | 5QI ∈ {65, 66, 69, 70} 或Emergency_Flag = 1 | MCPTT集群通话、公共安全通信、急救 | 规避前预处理窗口（PAW）开始后立即触发，优先抢占目标波位资源 |
| P2（实时GBR） | GBR > 0 且 5QI ∈ {1, 2, 3, 4} | VoNR语音、视频会议、实时游戏 | PAW前60%时间内完成切换；超时则增加候选目标数重试 |
| P3（交互Non-GBR） | GBR = 0 且 5QI ∈ {5, 6, 7, 8, 9} | Web浏览、流媒体 | PAW内完成切换（排在P2之后） |
| P4（后台Non-GBR） | GBR = 0 且 5QI ≥ 10 或尽力而为类 | 文件下载、邮件同步 | PAW剩余时间不足时，执行"挂起"替代切换，规避结束后自动恢复 |

**PAW时间资源分配**：

规避前预处理窗口（PAW，Pre-Avoidance Window）总时长T_PAW由SCF在配置信息中指定（默认3秒）。QAS按以下比例分配时间配额：P1立即触发（不占配额），P2占T_PAW×60%，P3占T_PAW×30%，P4使用剩余10%（不足则执行挂起）。前一优先级若提前完成，剩余时间顺延给下一优先级。

**P4 UE"挂起+自动恢复"机制**：

QAS向PAW内未能完成切换的P4 UE发送RRCRelease消息（携带suspendConfig参数），UE进入Suspended状态保留上下文；干扰规避时段[start, end]结束后，S-gNB主动向挂起UE发送寻呼，触发RRC恢复流程，UE通过随机接入恢复连接，缓存数据续传（支持最长挂起时长T_suspend_max，默认60秒，超时后释放上下文）。

#### 技术方案二：目标波位容量感知选择算法（CATS）

QAS在选择切换目标波位时，在候选波位集合（经覆盖时间刷新算法筛选后）中，追加以下容量约束：

**容量余量定义**：
```
C_margin = C_total - C_used - C_reserved
```
其中C_total为目标波位总容量，C_used为当前已用容量，C_reserved为该波位已为其他待切入UE预留的容量。

**容量筛选规则**：对P1/P2（GBR承载）UE，要求目标波位满足 C_margin ≥ GBR_i（该UE的GBR需求），否则从候选集中剔除该波位；对P3/P4 UE，无容量下限约束。

**综合评分排序**：对满足约束的候选波位，按以下评分降序排列，取得分最高者作为切换目标：

```
Score = w1 × ECD_normalized + w2 × (C_margin / C_total)
```

其中ECD_normalized为归一化有效覆盖时间（见技术方案三），w1 = 0.7，w2 = 0.3（可配置）。若所有候选波位容量均不足，则上报SCF，由SCF协调相邻卫星承接溢出用户。

#### 技术方案三：含QoS约束的增强版有效覆盖时间刷新算法

**基础操作**：从原始覆盖时间段[A1, A2]中剔除各干扰规避时段（采用保守剔除策略，各边界向外扩展0.5 ms以防边界对齐误差），得到若干不连续有效覆盖子段。

**GBR业务增强策略（GMCC约束）**：

对P1/P2（GBR业务）UE，要求候选目标波位存在至少一个连续有效覆盖子段的时长满足保证最短连续覆盖时长要求（GMCC，Guaranteed Minimum Continuous Coverage），其中：

```
GMCC = max(T_session_remain, GMCC_min)
```

T_session_remain为当前会话的估计剩余时长（若可知），GMCC_min为系统配置的最小连续覆盖保证（默认30秒）。

选段策略：按子段时长降序遍历，返回第一个满足 segment.duration ≥ GMCC 的子段作为有效覆盖时间参考；若无满足GMCC的子段，则剔除该候选波位。此策略避免选入覆盖时间碎片化（被多个规避时段切割）的目标，减少GBR业务的二次切换。

**Non-GBR业务策略（累计有效覆盖时长）**：

对P3/P4（Non-GBR业务）UE，有效覆盖时间定义为所有有效子段时长之和（累计值），允许业务在规避时段内短暂中断后续传，要求累计有效覆盖时长 ≥ Non_GBR_min_coverage（默认30秒）。

#### 技术方案四：增量差分Bitmap（Delta-Bitmap）更新机制

**更新方式选择逻辑**：

SCF在更新已下发的干扰规避配置时，首先统计本次更新中发生IRL等级变化的波位数量Changed_Count：
- 若 Changed_Count ≤ Threshold_Delta（增量更新阈值，默认63），则采用增量Delta-Bitmap更新；
- 若 Changed_Count > Threshold_Delta，则采用全量Bitmap更新（原有方式）。

**增量更新命令（DUC）数据包结构**：

新增命令类型（命令类型码建议0x0009），包头字段：

- Cmd_Type（8比特）：0x0009，标识为Delta更新命令；
- Total_PKT（16比特）/ PKT_Index（16比特）：与全量更新相同的分包控制字段；
- RCV——基准配置版本号（32比特）：本次增量更新所基于的全量配置版本号；
- New_Ver——新配置版本号（32比特）：本次更新生效后的版本号；
- Changed_Count（16比特）：发生变化的波位总数；

变化波位描述（每个变化波位4字节）：

- Beam_Index（16比特）：变化波位的编号（0 ~ N_beam-1）；
- New_IRL（2比特）：该波位更新后的IRL等级（00/01/10/11）；
- New_PAA_Mode（3比特）：对应的PAA工作模式；
- Reserved（11比特）：保留供扩展。

**传输效率对比**（以三层Bitmap全量更新为基准）：

| 场景 | 全量更新数据量 | Delta更新数据量 | 节省比例 |
|-----|------|------|------|
| 仅10个波位变化（K=10） | 192字节 | 6+10×4 = 46字节 | 约76% |
| 20个波位变化（K=20） | 192字节 | 6+20×4 = 86字节 | 约55% |
| 47个波位变化（K=47） | 192字节 | 6+47×4 = 194字节 | 约0%（平衡点） |

**版本一致性保障机制**：

S-gNB接收DUC后，校验本地生效版本号Local_Ver与RCV是否一致：
- 一致：执行增量更新，将Changed_Count个变化波位的IRL等级和PAA模式更新至本地配置镜像，将Local_Ver更新为New_Ver；
- 不一致：返回版本不一致错误响应（含Local_Ver），SCF收到后立即发送最新全量配置，覆盖S-gNB当前配置，后续继续使用增量更新。

S-gNB维护"当前生效配置镜像"（按波位索引直接访问），Delta更新仅修改对应条目，执行效率高；全量更新则整体刷新镜像。增量更新在S-gNB侧原子性生效（全部波位变化同时生效，不出现中间状态）。

### 3、在本发明技术方案基础上的改进与变形

（1）**优先级级数简化**：可将P1~P4四级简化为两级（GBR/Non-GBR），以更简单的方式实现优先级切换；两级分类同样属于本发明"基于QoS参数建立多级切换优先级队列"的保护范围；

（2）**挂起替代方式变形**：P4 UE的暂停服务除RRC挂起外，也可通过MAC层暂停调度（不向UE发送RRC消息）实现，规避结束后恢复调度，实质相同；

（3）**Delta-Bitmap编码方式替换**：变化波位信息可改用差分索引编码（对排序后的Beam_Index编码相邻差值）进一步压缩，或改用哈夫曼编码，实质均为"仅传输变化波位信息"的增量更新；

（4）**GMCC约束执行位置**：GMCC约束可由S-gNB侧执行（本发明方案），也可通过UE侧切换拒绝逻辑实现（UE拒绝接受不满足GMCC的目标波位），两种路径均属本发明的技术实质；

（5）**T_PAW动态调整**：PAW时长可根据波位内UE数量和历史切换时延动态调整（UE多则PAW更长），使切换调度与实际业务复杂度适配；

（6）**容量感知选择扩展至跨星**：当单星所有候选波位容量均不足时，CATS算法可扩展为跨星选择（查询相邻卫星的候选波位容量），实现跨星容量均衡切换。

### 4、有益效果

（1）**高价值业务连续性大幅提升**：P1/P2优先级保障机制确保紧急通信和实时GBR业务在PAW内优先完成切换，切换成功率可达98%以上（典型负载场景估算），远高于无优先级时的随机中断风险；

（2）**系统资源利用率更优**：P4"挂起+恢复"机制避免了低优先级业务在规避时段短（如小于60秒）场景下的无效切换信令开销，减少目标波位资源不必要占用，提升系统整体资源利用率；

（3）**GBR业务切换稳定性提升**：GMCC约束使切换目标选择优先保证GBR业务的连续覆盖质量而非仅看总覆盖时长，可减少GBR业务切换乒乓次数约30%（理论估算），降低二次切换对GBR承载的影响；

（4）**配置更新效率显著提升**：Delta-Bitmap在典型星历修正场景（K ≤ 20个波位变化）下，传输数据量从192字节降至约86字节，节省约55%；多星并发配置更新时，S-C1链路聚合带宽需求大幅降低，配置更新响应时间缩短，支持更高频的规避配置刷新；

（5）**配置更新正确性有机制保障**：版本一致性校验和全量回退机制防止增量更新在版本不一致时静默出错，保证系统配置的最终一致性。

**图3：含GMCC约束的有效覆盖时间刷新算法对比示意图**

```
原始覆盖时间段 [A1 ─────────────────────────────────────── A2]
               │                                           │
               │←──────────── 总时长 120秒 ───────────────→│

规避时段（剔除区域）：
               │        ████████        ████████           │
               │←25s→│←─20s─→│←─35s─→│←─15s─→│←─25s─→│
               │  子段1  规避1   子段2   规避2    子段3     │
               │   25秒        35秒（最长）       25秒     │

─────────────────────────────────────────────────────────────────────
(a) 原有算法（取最长子段，不考虑GMCC约束）：

    子段时长：  [25秒]    [35秒] ← 最长子段    [25秒]
    GMCC=30秒：  不满足   满足（35≥30）          不满足

    原有算法选择：子段2（35秒）← ✓ 正确（碰巧满足GMCC）

─────────────────────────────────────────────────────────────────────
(b) 反例场景（说明原有算法的缺陷）：

    假设另一波位的子段分布为：
    子段时长：  [40秒]    [25秒]    [20秒]
    GMCC=30秒：  满足    不满足     不满足

    原有算法选择：子段1（40秒）← ✓ 最长且满足GMCC，结果正确

    再假设子段分布为：
    子段时长：  [28秒]    [32秒]    [15秒]
    GMCC=30秒：  不满足   满足      不满足

    原有算法：取最长=32秒 → 满足GMCC ✓ 无问题

    极端反例：
    子段时长：  [26秒]    [24秒]    [22秒]（最长26秒 < GMCC=30）
    GMCC=30秒：  不满足   不满足    不满足
    原有算法选择子段1（26秒）→ 实则不满足GBR连续覆盖要求！
    增强算法：遍历后无满足GMCC的子段 → 剔除该候选波位 ✓

─────────────────────────────────────────────────────────────────────
增强算法伪代码（GMCC约束）：

  SELECT_ECD_GBR(Segments, GMCC):
    按时长降序排列 Segments
    FOR each segment in sorted order:
      IF segment.duration >= GMCC:
        RETURN segment   ← 返回第一个满足GMCC约束的子段
    RETURN None          ← 无满足的子段，剔除该候选波位

Non-GBR业务（累计策略）：
  ECD_NonGBR = Σ segment.duration ≥ Non_GBR_min（默认30秒）
  （允许不连续，多段累计计算）
```

图3说明：展示含GMCC（保证最短连续覆盖时长，默认30秒）约束的增强版有效覆盖时间刷新算法，对比原有"取最长子段"策略的差异。增强算法按子段时长降序遍历，返回第一个满足GMCC约束的子段，若无满足的子段则剔除该候选波位，从根本上避免选入"覆盖时间总量大但均不满足连续性要求"的目标波位，减少GBR业务切换后的乒乓效应。

## 六、具体实施方式

以某LEO卫星业务波束第50号波位因干扰规避（IRL-3）需在T_start时刻关断为例，说明本发明的具体实施过程。

**场景设定**：第50号波位当前有在网UE共20个，具体分布：MCPTT集群通话用户2个（P1）、VoNR语音用户5个（P2）、Web浏览用户8个（P3）、文件下载用户5个（P4）。PAW时长T_PAW = 3秒，规避时段约60秒。

**步骤一：QAS初始化切换队列（T_start前3秒触发，即PAW开始）**

QAS从UE上下文读取各UE的5QI/GBR参数，分类结果：P1队列（2个MCPTT用户）、P2队列（5个VoNR用户）、P3队列（8个Web用户）、P4队列（5个文件下载用户）。PAW时间分配：P2时间配额 = 3×60% = 1.8秒，P3配额 = 3×30% = 0.9秒，P4配额 = 0.3秒。

**步骤二：P1/P2切换执行（PAW第0~1.8秒）**

QAS对P1队列2个MCPTT用户立即触发切换，CATS算法从候选波位（第51、52、53号波位）中筛选：

首先执行覆盖时间刷新（GMCC约束：GMCC_min = 30秒），第51号波位覆盖时间在未来60秒内有一个25秒连续子段，不满足GMCC，剔除；第52号波位最长连续子段40秒，满足GMCC且C_margin = 35%（剩余容量），Score_52 = 0.7×(40/60) + 0.3×0.35 = 0.572；第53号波位最长连续子段35秒，C_margin = 60%，Score_53 = 0.7×(35/60) + 0.3×0.60 = 0.589，得分更高。2个MCPTT用户切换至第53号波位，S-gNB为其预留GBR资源（各需2 Mbps × 2 = 4 Mbps）。随后对P2队列5个VoNR用户执行类似流程，均于1.8秒内完成切换。

**步骤三：P3切换执行（PAW第1.8~2.7秒）**

8个Web浏览用户（Non-GBR）按累计有效覆盖时长选择目标，优先选C_margin最大的候选波位，7个切换成功，1个因目标波位突发满载切换失败（进入重试）。

**步骤四：P4处理（PAW第2.7~3.0秒）**

5个文件下载用户中，剩余PAW时长仅0.3秒，仅1个完成切换，其余4个由QAS执行挂起：向4个UE发送RRCRelease with suspendConfig，UE进入Suspended状态。

**步骤五：规避结束后恢复（60秒后）**

规避时段结束，S-gNB向4个挂起UE发送寻呼，触发RRC恢复，4个UE通过随机接入恢复连接，文件下载续传（数据从S-gNB侧缓存中继续发送）。用户未感知到会话中断。

**Delta-Bitmap增量更新示例**：

5秒后SCF收到新星历修正，仅第48、50、53号波位的IRL等级发生变化（Changed_Count = 3 < Threshold_Delta = 63），SCF生成DUC：包含RCV（当前版本号）、New_Ver（新版本号）、Changed_Count = 3，以及3个变化波位的描述（Beam_Index=48, New_IRL=01, New_PAA_Mode=001；Beam_Index=50, New_IRL=11, New_PAA_Mode=011；Beam_Index=53, New_IRL=00, New_PAA_Mode=000）。总数据量 = 6 + 3×4 = 18字节，相比全量Bitmap的192字节减少约91%。S-gNB校验版本号一致后，原子性更新3个波位的配置镜像，Local_Ver更新为New_Ver，上报确认响应。

## 七、技术创新点概括

本方案重点要保护如下几方面的创新点：

1）**干扰规避触发切换场景下的UE四级优先级分类规则及PAW分时段调度机制**：以5QI和GBR属性为依据，将UE分为P1（紧急通信）/P2（实时GBR）/P3（时延敏感Non-GBR）/P4（后台Non-GBR）四级，在规避前预处理窗口（PAW）内按P1立即触发、P2占60%、P3占30%、P4用剩余的比例分时段调度切换，首次将5QI/GBR优先级体系引入干扰规避场景的切换资源编排；

2）**P4 UE的"RRC挂起+规避结束自动恢复"机制**：当PAW时间不足以完成P4 UE切换时，由QAS主动向P4 UE发送RRCRelease with suspendConfig（保留上下文），于规避时段结束后自动触发RRC恢复，实现"资源不抢占、会话不丢失"，区别于现有技术的强制切换或强制中断；

3）**目标波位容量感知选择算法（CATS）**：在覆盖时间和RSRQ筛选基础上，新增 C_margin ≥ GBR_i 的容量余量约束（仅对GBR业务UE），并引入 Score = w1×ECD_normalized + w2×(C_margin/C_total) 综合评分排序，避免选入虽覆盖时间充裕但已满载的目标波位；

4）**含GMCC约束的GBR业务有效覆盖时间增强算法**：要求GBR业务候选目标波位的最长连续有效覆盖子段时长 ≥ GMCC，以及"遍历降序子段、返回第一个满足GMCC的子段"的选段策略，区别于现有技术仅取最长总时长的简单策略，可减少GBR业务切换乒乓效应；

5）**增量Delta-Bitmap更新命令（DUC）数据结构及版本一致性保障机制**：DUC包含4字节/波位的变化描述（Beam_Index 16bit + New_IRL 2bit + New_PAA_Mode 3bit + Reserved 11bit），配合RCV基准版本号校验和全量回退机制，在仅少量波位状态变化时可减少55%以上的传输数据量，同时保证配置更新的正确性。
